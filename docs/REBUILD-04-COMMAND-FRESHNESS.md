# REBUILD-04 명령 만료와 적용 버전

2026-09-15. [개발방향](CherryPulse-KR-01-Development-Direction.md), [실행 계약](REBUILD-02-CONTRACTS.md), [전송 직전 검증 기록](REBUILD-04-REQUEST-FAILURES-AND-LOCK.md)의 후속 구현이다.

## 동작

- 주문 명령에 시간대가 있는 `expires_at`을 추가했다. `now >= expires_at`이면 COMMAND_EXPIRED로 거절한다. 증권사 주문 조건인 DAY와 로컬 요청의 유효 기한은 별개다.
- 새 요청 접수와 SENDING 기록 직전에 만료·적용 버전을 확인한다. 검사는 각각 해당 SQLite 트랜잭션 안에서 수행한다. 차단 시 전송 기록·가상 호출·추가 예약은 발생하지 않는다.
- 동일 키·동일 내용 재조회는 원래 요청을 반환하며 유효 기한을 연장하지 않는다. 같은 키의 만료 시각을 바꾸면 CONFLICT_IDEMPOTENCY_MISMATCH다.
- `apply_config(symbol, expected_version, version)`은 현재 적용 버전과 기대 버전의 일치 및 버전 증가를 확인하고 config 사실을 원장·outbox에 함께 기록한다. DB 재로드 후에도 유지되며 재시작 검토 revision에도 포함된다.
- 요청의 config_version이 현재 적용 버전과 다르면 STALE_CONFIG_VERSION으로 접수·전송을 차단한다. 가상 청산이 새로 만드는 매도 요청에는 현재 적용 버전을 사용한다.
- `Ledger`에 시계를 주입할 수 있어 경계 시각을 sleep 없이 검사한다. 기본 시계는 UTC 현재 시각이며 시간대 없는 주입 시계는 거절한다.

## 가상 구현의 한계

기존 내부 시나리오의 초기 적용 버전은 1이다. expires_at 생략은 기한 없는 내부 가상 의도를 뜻한다. 이는 외부 웹 명령에 무기한 실행을 허용한다는 계약이 아니다. 향후 웹 명령 경계에서 인증·권한·기한 필수 정책을 구현해야 한다.

적용 버전 기록은 실제 패턴 내용의 저장·수락이나 보유 보호 규칙의 교체가 아니다. 이 구현은 버전 번호의 일치와 증가만 보장한다. 실제 설정 모델·보호 규칙 인계·재시도 멱등성은 후속 작업이다. 현재 apply_config 호출 자체는 웹 명령 멱등 API가 아니며, 재호출 시 기대 버전이 오래되면 거절한다.

기존 요청이 만료되거나 버전이 달라져도 원장을 삭제하거나 예약을 자동 해제하지 않는다. 명시적인 폐기·재작성 절차가 필요하다. 기존 취소·정정 명령도 만료·버전을 검사하므로 설정 변경 후에는 현재 버전으로 새로운 의도를 작성해야 한다. 시계 역행 감지·시간 동기화 장애 정책은 미구현이다.

## 확인 결과

- 신규 검사 7개를 포함한 전체 pytest **72개 통과, 6.94초**.
- 만료 경계, 기한 직전 정상 전송, 만료 이후 재조회, 같은 키의 만료 연장 거절, 적용 버전 변경 후 전송 차단, 오래된 기대 버전 거절, DB 재로드 후 오래된 명령 거절을 검사했다.
- Ruff ALL 및 basedpyright 오류·경고 0. 코드 규칙 27개 파일 위반 0.
- 별도 임시 DB의 직접 가상 실행에서 만료 경계 COMMAND_EXPIRED, 가상 호출 0, 전송 상태 INTENT_PERSISTED 유지, 적용 버전 2 저장을 관측했다.
- 기존 모듈 데모는 관리량 70·예약 0·가상 호출 2·재생 변경 0을 유지했다.

증권사 로그인·주문 API·배포는 실행하지 않았다. 운영 DB와 back/ 보관본을 변경하지 않았다. 다음은 미전송 의도의 명시적 폐기와 예약 해제, 대조 해소 근거, 외부 명령 인증·권한 및 실제 설정 계약이다.

미전송 의도의 명시적 폐기·예약 해제는 [후속 구현 기록](REBUILD-04-DISCARD.md)에서 완료했다. 최신 전체 검사 수는 78개이며 실제 계좌 연동 완료를 뜻하지 않는다.
