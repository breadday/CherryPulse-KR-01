# REBUILD-04 가상 수량 불일치 대조 해소

2026-09-15. [미전송 의도 폐기](REBUILD-04-DISCARD.md) 다음 개발 단위다. [실행 계약](REBUILD-02-CONTRACTS.md)의 증거 보존·수량 자동 보정 금지 원칙을 따른다.

## 구현 범위

불일치 ID 하나에 연결되는 RECONCILED 사실을 추가했다. 종목, 확인한 관리 수량, 검토 원장 revision, 근거 참조 코드와 VIRTUAL_COMPLETE_REVIEW 출처를 기록한다. `Ledger.ingest`의 기존 트랜잭션·중복 검사·outbox 경로를 사용한다.

허용 조건은 다음과 같다.

1. 같은 종목·ID의 원래 DISCREPANCY가 존재하고 아직 해소되지 않았어야 한다.
2. 검토 revision이 현재 원장과 일치해야 한다. 검토 후 체결·설정·제어 등 다른 기록이 추가됐다면 다시 검토한다.
3. 해당 종목의 요청 전송·효과가 미확정이거나 주문 수량이 충돌하면 해소를 거절한다.
4. 확인한 관리 수량이 원장이 계산한 관리 수량과 일치해야 한다. 다른 수량을 입력해도 배정·체결·보유를 수정하지 않는다.

하나를 해소해도 다른 불일치와 주문 충돌은 남는다. 같은 이벤트 재수신은 추가 변화가 없고, 다른 이벤트로 이미 해소한 근거를 덮어쓰려 하면 거절한다. 새로운 불일치가 들어오면 다시 차단한다. 원래 불일치와 해소 사실을 모두 보존한다.

재시작 검토의 종목 집합에도 DISCREPANCY를 포함했다. 기존에는 주문·배정이 전혀 없는 종목의 불일치가 검토에서 빠질 수 있었으며, 실패하는 검사로 재현한 뒤 수정했다.

## 해석과 제한

이 기록은 신뢰된 가상 시나리오의 완전한 검토 결과를 받는 내부 모델이다. proof_reference는 근거 식별 코드이며 실제 증권사 조회 원문이나 증명 자체가 아니다. 외부 입력자가 해당 문자열을 보냈다는 이유로 실계좌 대조를 승인하는 API로 노출하면 안 된다.

실제 적용에는 조회 시작·종료 시각, 이벤트 경계, 페이지 완전성, 주문·체결·미체결·잔고와 외부 배정 구분을 확인하는 어댑터가 필요하다. 계좌 총보유를 observed_managed에 그대로 넣지 않는다. 키움 조회 확인, 원문 격리, 인증·권한과 운영자 승인 이력은 미구현이다.

RECONCILED는 일반 DISCREPANCY 해소에만 사용한다. 주문 상태 충돌이나 UNKNOWN을 정상으로 바꾸지 않는다. 그 경우 연결된 접수·체결·취소 등의 실제 근거를 별도로 반영해야 한다. 해소 기록 수신은 재시작 전송 게이트를 자동으로 열지 않는다. 기존의 최신 원장 검토 단계는 별도로 유지한다.

## 검증 결과

- 신규 8개 포함 전체 pytest **86개 통과, 6.66초**.
- 개별 해소·다른 불일치 유지, 수량 불일치 거절, 오래된 검토 거절, 미확정 취소·주문 수량 충돌 보존, 없는 대상 거절, 근거 덮어쓰기 방지, 불일치만 있는 종목의 시작 차단을 검사했다.
- Ruff ALL·basedpyright 오류/경고 0. 포맷 및 코드 규칙 29개 파일 통과.
- 별도 임시 DB 직접 실행에서 차단 True → 해소 후 DB 재로드 False, 관리량 100 유지, 중복 수신 변화 False, 원래 불일치 보존 True를 확인했다.

실제 증권사 호출·주문·배포·운영 DB 변경은 수행하지 않았다. 다음은 연결 불명확 이벤트의 원문 격리와 재처리 계약, 실제 조회 근거 모델, 외부 명령 인증 및 패턴 상세 설정이다.

가상 체결의 격리·주문번호 연결·원자적 재처리는 [후속 기록](REBUILD-04-QUARANTINE.md)을 따른다. 최신 전체 검사는 92개 통과다. 실제 키움 원문 보관과 식별 규격 검증은 미완료다.
