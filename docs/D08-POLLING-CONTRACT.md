# D08 폴링 동기화 계약

- 최초 작성: 2026-10-11 / 사용자 결정 반영: 2026-10-12
- 상태: 결정된 정책 계약. 로컬 가상 동기화 구현 대상이며 Supabase 실연결·인증 검증은 미수행.

## 책임 분리

- Supabase: 원하는 설정(desired), 명령 전달, 표시용 복제 상태.
- Windows 로컬 SQLite: 적용 설정·요청·주문·체결·예약 원장. 실행 상태의 원본은 로컬 원장이다.
- 엔진이 로컬 적용을 수락하기 전 웹은 `감시 중`으로 표시하지 않는다. `APPLIED`도 로컬 기록 완료이며 감시 활성화를 뜻하지 않는다.
- 엔진 온라인 여부를 확인하지 못하면 `엔진 오프라인 - 마지막 동기화 n분 전`을 표시한다. 폴링 성공 전 하향 명령을 실행하지 않는다.

## 폴링·재시도

- 정상 폴링 간격 5초, 요청 timeout 3초.
- 네트워크 오류, HTTP 5xx, timeout만 재시도한다. 5초부터 지수 백오프하며 최대 대기는 5분이고, 성공 응답 뒤 5초 주기로 복귀한다.
- HTTP 4xx는 자동 재시도하지 않고 운영자 확인 상태로 둔다.
- 마지막 성공 동기화 후 5분은 보드 경고, 30분은 운영자 알림 기준이다. 외부 채널·수신자는 정해지지 않아 연결 전 상태다. 알림 실패는 로컬에 기록한다.

## 계정 권한·RLS·감사

- Supabase Auth 사용자 본인만 접근한다. 지정 운영자는 없다.
- 사용자가 웹 관리 화면에서 계좌·환경 권한을 직접 부여·회수한다.
- `auth.uid() = owner` 및 계좌·환경 명시 연결이 모두 맞을 때만 읽기/쓰기 허용. 나머지는 기본 거부한다.
- 권한 변경·명령·설정 변경 감사 이력은 1년 보존하며 법규상 필요하면 연장한다.
- 인증 토큰과 키는 저장소·문서에 기록하지 않는다.

## 하향 명령 순서와 충돌

- 조회 범위는 계좌·환경이며 서버가 발급한 단조 증가 정수 순번 오름차순으로 처리한다.
- 서버 순번과 `expected_version`이 모두 현재 로컬 기대값과 맞는 명령만 기존 `ConfigInbox.receive` → 적용 절차로 전달한다. 동기화 계층에서 별도 설정 적용 경로를 만들지 않는다.
- 같은 ID/멱등 키와 내용이 같으면 기존 결과를 반환한다. 같은 키의 내용 변경은 충돌이다.
- 충돌·역순·오래된 버전은 자동 병합하지 않고 거절한다. 사용자는 보드에서 최신 설정을 다시 불러와 재제출한다.
- 오프라인 상태에서 작성한 명령은 서버 수신 시각 기준으로 순번을 새로 발급한다. 더 높은 순번이 이미 적용된 뒤 도착한 명령은 거절한다.
- 서버가 더 높은 순번을 반환하지만 로컬이 그 앞 순번을 처리하지 못한 경우 건너뛰어 적용하지 않고 동기화 충돌 상태로 멈춘다.

## 상향 outbox

- 업로드 단위는 원장 순서와 이벤트 ID를 가진 이벤트다. 순번을 멱등 키로 사용해 재전송 중복을 제거한다.
- HTTP 200뿐 아니라 응답에서 해당 순번의 반영을 확인한 뒤에만 ACK 처리한다. 확인 전 로컬 outbox 항목을 삭제하지 않는다.
- ACK 뒤에도 로컬 원장에 7일 유지하고, 이후 압축 보관 30일을 거친다. 삭제는 별도 운영 보존 정책에 따른다.
- ACK가 불명확하면 전송 성공으로 표시하지 않고 같은 멱등 키로 재시도한다. 서버에서 같은 키·다른 내용이면 격리·운영자 확인 상태로 둔다.

## 실패·중지 정책

- 폴링/업로드 실패는 로컬 원장이나 감시 설정을 변경하지 않는다. 마지막 성공 시각과 실패 원인을 기록한다.
- 4xx 또는 인증/권한 오류는 재시도하지 않으며 운영자 확인 전 하향 명령 적용을 막는다.
- `UNKNOWN` 전송·적용 결과를 성공이나 실패로 추정하지 않는다. 명시적 대조/재개 경로를 사용한다.
- 실제/모의 주문 API, 운영 DB 변경, 배포는 별도 명시 요청 없이 수행하지 않는다.

## 미정 항목과 구현 경계

- Telegram을 외부 알림 채널로 선택했다. 로컬 봇 토큰/개인 채팅 ID와 송신기 연결 전에는 Telegram 전송을 비활성화하며, 로컬 상태 기록·보드 경고는 구현 가능하다.
- 서버 테이블, 저장소 계정 설정 및 RLS 정책은 사용자 계정이 연결된 후 적용한다. 이 계약은 schema 또는 migration을 실행했다는 뜻이 아니다.
- D08 로컬 fake transport/가상 재생은 구현 가능하다. 실제 Supabase credentials, 운영 테이블, 네트워크 연결은 사용하지 않는다.
