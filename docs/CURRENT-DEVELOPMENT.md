## 사용 가능한 기능

- 통합 대시보드 7개 메뉴, 종목 검색, 키움 모의 최근 체결가 조회, 금액 계산, 로컬 초안과 보드 PIN 기반 서버 예약 등록·수정·취소를 제공한다. 계좌 조회는 별도의 열람 키로 보호한다.
- Supabase pg_cron이 매분 서버 예약의 KST 실행 시각을 확인한다. 검증된 2026년 KRX 영업일에만 DRY_RUN 결과를 기록한다. 지연 허용 범위는 지정 시각부터 2분 미만이다. 허용 구간이 지난 건과 도입 전 이미 만료된 건은 처리하지 않는다.
- 실행기 트랜잭션 잠금과 예약별 결과 기본 키가 중복 처리를 막는다. 중단 시 미커밋 처리는 롤백되고 다음 검사에서 유효한 예약을 다시 읽는다. 검증 오류는 예약별 오류 코드로, 작업 자체의 실패는 cron 작업 이력에 남는다.
- 주문·예약 화면에 대기, 시각 도달, 모의 검증 완료, 만료, 취소, 오류를 표시한다. 예정 시각과 실제 처리 시각은 각각 KST로 표시하며 열린 예약 화면은 15초마다 갱신한다.
- 실행 결과는 전용 DB 테이블에 보관한다. 실행 경로는 DB 내부 SQL만 호출한다. 키움 실주문, 모의주문, 자동매매는 모두 OFF다.

## 소유자 PIN 복구와 모의주문 준비

- 운영·설정에서 PIN 설정 여부를 조회한다. 프로젝트 소유자 또는 승인받은 관리자가 Supabase SQL Editor에서 'select cherrypulse_private.issue_owner_pin_recovery();'를 직접 실행한다. 발급된 256비트 코드는 10분간 1회만 사용할 수 있다. 코드와 새 4자리 또는 6자리 PIN을 운영·설정 화면에 입력하면 저장과 기존 PIN 세션 폐기가 같은 트랜잭션에서 처리된다. 기존 4자리 PIN과 새로 설정한 6자리 PIN을 지원하며 로그인 시도 제한은 유지한다.
- 복구 코드 발급은 웹 API에 노출하지 않는다. PIN 원문은 조회하지 않았다. 실제 DB에는 PIN이 설정돼 있고, 적용 전후 소유자·예약·보드 스냅샷 비교가 일치했다. 새 PIN 로그인은 사용자가 확인했고, 실제 두 기기 간 동기화 검증은 남아 있다. 격리 환경에서는 PC 등록→모바일 재조회·수정→PC 취소→최종 상태 일치를 검증했다.
- 주문·예약의 모의계좌 사전검증은 현재 주문가능금액·매도가능수량을 조회한다. 시장가 매수는 종목 상한가를 기준으로 금액을 보수적으로 확인한다. KRX 매수 kt10000, 매도 kt10001의 시장가·지정가 요청 구조만 생성한다. 서버 전송기는 읽기 전용 TR 목록으로 제한되어 주문 URL을 거부한다.
- 주문·체결 화면은 계좌 열람 키를 사용해 당일 KRX 주문내역 kt00007 및 체결조회 ka10076을 분리해 표시한다. 실제 모의 REST에서 두 조회가 정상 응답했으며 확인 시 내역은 비어 있었다. 응답 지연·불명은 재주문으로 이어지지 않는다. 주문번호가 있는 신규 접수와 후속 체결의 대조 및 지속적인 전송 중복 방지 원장은 별도 승인 이후 전송 단계에서 검증해야 한다.
- 키움 계약은 https://openapi.kiwoom.com/m/guide/apiguide/13/kt10000 및 https://openapi.kiwoom.com/m/guide/apiguide/13/kt10001 기준이다. 실주문·모의주문·자동매매는 OFF이며 예약 DRY_RUN은 독립적으로 동작한다.

- 2026-11-24 PIN 저장 실패 수정. 운영 DB의 조건 없는 DELETE 보호와 충돌하던 로그인 세션 폐기를 유효 세션 범위로 제한했다. 실패한 저장은 트랜잭션 전체가 롤백된다. 화면은 코드 거부·입력 오류·서버 오류를 구분하며 저장 성공 후 입력을 지운다.

- 새 주문과 보유종목에서 연 주문은 수량 1주로 시작한다. 예약 수정 시 저장된 수량을 복원한다.
 - 서버 예약은 종목명·상태·실행 예정 시각·주문 조건을 나눈 카드로 표시한다.
 - 주문 수량과 지정가는 증감 버튼 또는 위·아래 방향키로 1주·1원씩 조정한다. 시장가에서는 지정가 조절을 잠근다. 선택 종목코드는 읽기 전용으로 표시한다.

## 계좌 기기 PIN

- PC에서 기존 열람 키와 6자리 PIN으로 브라우저를 등록한다. PC에서 PIN을 다시 확인해 3분간 유효한 12자리 일회용 연결 코드를 발급한다. 휴대폰에서는 연결 코드와 같은 PIN만 입력한다.
- 기기 쿠키는 Secure·HttpOnly·SameSite=Strict이며 유효기간은 90일이다. PIN으로 얻는 계좌 열람 권한은 해당 브라우저에서 15분간 유효하다. 5회 연속 실패 시 해당 기기의 PIN 인증을 차단한다. PC는 기존 열람 키로 재등록하고 휴대폰은 새 연결 코드로 재등록한다. 등록 기기의 PIN 인증은 기존 보드 소유자의 15분 세션도 발급한다.
- 기기·연결 코드 테이블과 서버 전용 비밀값을 검증하는 두 RPC를 운영 Supabase에 설치했다. 실제 PC·휴대폰의 등록 및 재접속은 사용자 확인이 필요하다.
- 예약 로그인과 소유자 PIN 변경은 숫자 4자리 또는 6자리를 지원한다. 기존 보드 복구 경로의 PIN 값과 예약 데이터는 그대로 유지된다. 통합 화면의 일반 로그인은 등록 기기 6자리 PIN을 사용한다.
- 예약 로그인 실패 시 입력값을 유지한다. 보드 PIN 불일치, 로그인 후 쿠키 미유지, 서버 목록 조회 실패를 구분하며 로그인과 목록 조회가 모두 성공한 뒤 PIN을 지운다.

- 등록 기기 6자리 통합 PIN으로 계좌, 주문·체결 내역, 서버 예약 조회·등록·수정·취소, 내장 관심종목 보드 조회·저장을 사용한다. 세션 쿠키는 HttpOnly·Secure·SameSite=Strict이며 서버 만료는 15분이다. 실제 기기 로그인은 사용자 확인 대기다. 실주문·모의주문 전송 및 자동매매는 OFF다.
- 서버 예약 카드 첫 줄에 주문 방향을 표시한다. 매수는 빨간색, 매도는 파란색 배지이며 실행 상태는 별도로 표시한다.

## 수동 모의매수 1건과 당일 체결 조회

- `python -m tools.submit_paper_buy --symbol <종목코드> --price <지정가>`는 네트워크 없이 모의 환경, 매수 방향, 종목, 고정 수량 1주, 지정가를 표시한다. 승인 후 접수된 주문은 당일 중복 방지 파일에 주문번호의 앞자리 0을 보존한 SHA-256 해시를 기록한다.
- `node tools/check_paper_buy.js`는 당일 파일과 키움 모의 주문·체결 내역을 대조한다. 주문 접수 응답만 있으면 ACKED, 수량이 대조되면 UNFILLED·PARTIALLY_FILLED·FILLED를 표시한다. 1주 주문에서 부분체결은 발생할 수 없어 합성 다수량 사례로 검증했다.
- 전송 결과 불명·주문번호 누락·잘못된 번호는 당일 재전송을 차단한다. CHECK_ORDER_HISTORY 안내가 나오면 주문·체결 화면에서 확인한다. 구버전 파일에는 번호 해시가 없어 수동 대조가 필요하다.
- 오프라인에서 Node 79건과 Python 3.14 주문 도구 테스트 15건이 통과했다. 증권사의 실제 접수번호 및 체결 대조는 별도 확인 사항이다. 이 개발 검증에서는 주문을 전송하지 않았다.
