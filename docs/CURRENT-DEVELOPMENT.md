# CherryPlus 현재 개발

2026-11-24 기준 목표는 키움 국내주식 REST 중심 통합 대시보드 UI 완성이다. 현재 브랜치는 design/unified-trading-dashboard-20261121이며 서버 예약 작업의 기준 커밋은 f87a96f이다. 최신 구현 커밋은 git log -1 -- web/api/reservations.js 로 확인한다. 과거 전환 문서의 미완료 항목은 이번 범위에 추가하지 않는다.

## 화면과 연동

- 통합 홈, 관심종목·패턴 보드, 계좌·보유종목, 주문·예약, 주문·체결, 자동매매, 운영·설정으로 이동한다. URL 해시로 새로고침과 뒤로가기를 지원한다.
- 기존 종목 목록 3,488행에서 검색하고 키움 모의 REST 최근 체결가와 시각을 조회한다. web/market-data.js가 대시보드의 목록·시세 읽기 인터페이스다. 전체 상장시장 실시간 동기화는 미구현이다.
- 지정가 계산, 예수금·예비금 직접 입력, 시장가 금액 미확정, KST 예약 미리보기, 브라우저 초안 확인·수정·취소를 지원한다. 2026년 이후 거래소 일정은 미등록이다.
- 키움 모의 REST의 예수금·주문가능금액과 KRX 보유종목을 읽기 전용으로 조회한다. 서버에서 기존 시세 인증을 공유한다. 계좌 화면과 홈은 조회 완료 시각(KST)을 표시하고 실패·잠금 시 이전 값을 지운다. 체결·전략 실행 기록은 미연결이다. 전략과 주문 실행은 OFF다. 즉시 주문은 입력 확인까지만 가능하다.

- 미리보기 전용 Vercel 배포 dpl_CakyyRfnDodkLxwk42e6FrgtGc3s 를 https://cherryplus-ui-preview.vercel.app/ 에 연결했다. 고정 주소에서 새 스크립트와 005930 모의 최근 체결 응답을 확인했다.

## 2026-11-24 계좌 조회 인계

- PR #33의 기존 화면과 예약 초안을 유지했다. 모의 호스트로 고정한 서버 인증, 예수금 kt00001, 계좌평가잔고 kt00018 및 연속 조회를 적용했다. 제공되지 않은 숫자는 대시로 표시한다. 보유종목을 선택하면 주문 화면에 이름과 코드가 전달된다.
- 로컬에서 환경변수의 모의 키로 인증·조회하고 Chrome 1440px·390px에서 실제 응답과 화면에 표시한 계좌 금액 및 보유종목 각 열을 대조했다. 실제 보유종목 선택과 7개 메뉴 이동을 확인했다. 빈 목록, 인증 실패, 타임아웃은 테스트 응답으로 검증했다. 기존 Node 64건과 추가 3건 통과.
- 미리보기 전용 배포 dpl_2tKwD4m2L4aswZBfWHDYyr6kVTP8. 고정 주소에서 계좌 UI, 시세 함수, 계좌 요청의 HTTP 503 SETUP_REQUIRED를 확인했다. 공개 사이트에서는 계좌 내용이 노출되지 않는다.
- 공개 미리보기의 개인 열람 설정은 대기 중이다. Vercel cherryplus-ui-preview 프로젝트의 Production에 CHERRYPLUS_ACCOUNT_VIEW_KEY를 별도의 무작위 32자 이상 비밀값으로 등록하고 재배포한다. 계좌 화면에서 같은 열람 키를 입력한다. 키움 앱 키와 토큰은 서버 전용이다. 로그인된 배포 화면과 실제 잔고의 대조는 이 설정 후 수행한다.
## 서버 예약 관리

- 주문·예약 화면에서 기존 보드 PIN으로 로그인하면 서버 예약을 등록·조회·수정·취소한다. PC와 휴대폰은 같은 소유자 목록을 읽는다. 기존 브라우저 초안은 유지하며 초안을 수정 화면으로 열어 미리보기 후 서버 예약으로 저장할 수 있다.
- Supabase 프로젝트를 일시 중지에서 복구하고 서버 예약 마이그레이션을 적용했다. DB에서 소유자 PIN 설정 여부, 비인증 RPC 401 및 익명 테이블 읽기 권한 없음을 확인했다. 서버 예약 API는 계좌 열람 키 및 키움 API와 독립적이다. 로그인 세션은 HTTPS 전용 HttpOnly 쿠키로 12시간 유지한다.
- UUID·원본 요청·버전 및 활성 주문 내용의 고유 인덱스로 재시도 중복과 수정 충돌을 방지한다. 저장 시 DB가 KST 미래 시각과 등록된 2026년 KRX 영업일을 검증한다. 취소·만료는 수정할 수 없고 목록에서 상태를 확인할 수 있다. 예약 실행기·자동매매·주문 전송은 OFF다.
- Node 테스트 70건 통과. 별도 PostgreSQL 호환 테스트 DB에 마이그레이션을 적용하고 실제 API 핸들러와 Chrome 1440px·390px 독립 세션으로 등록→재조회→수정→취소→새로고침을 확인했다. 중복, 버전 충돌, 과거·휴장일·미등록 연도, 취소·만료 후 수정, 비인증 요청을 검증했다. 테스트 PIN과 테스트 예약만 사용했다.
- 고정 미리보기 배포 dpl_5C3mBt6w8XuUzx17zpxLDvLbhNNc. 새 화면 HTTP 200, 공개 예약 조회 HTTP 401, 계좌 조회 HTTP 503(열람 키 설정 대기)을 확인했다. 개인 PIN을 입력한 배포 환경의 기기 간 검증은 사용자 확인 사항이다. PR #33의 최신 CI 결과는 GitHub Actions에서 확인한다.
- 다음 확인은 고정 주소에서 두 기기에 같은 보드 PIN으로 로그인해 예약 관리 흐름을 확인하는 것이다. 2027년 일정을 사용하려면 검증된 거래소 달력을 추가한다.
