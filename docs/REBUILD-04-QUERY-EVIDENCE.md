# REBUILD-04 조회 완전성 근거

2026-09-16. [가상 체결 격리](REBUILD-04-QUARANTINE.md) 이후 대조 입력 계약을 보강한 기록이다.

## 구현한 계약

RECONCILED의 필수 query 필드에 QueryEvidence를 저장한다. query_id, 시간대가 있는 조회 시작·종료 시각, 시작·종료 원장 revision, 확인 관리량과 주문·체결·미체결·잔고의 네 조회 구간을 포함한다.

각 구간은 예상 페이지 수, 실제 받은 페이지 번호 목록, 마지막 응답 완료 여부, 오류 코드를 갖는다. 1부터 예상 페이지 수까지 중복·누락 없이 수신하고 오류 없이 완료된 경우에만 완전하다. 빈 조회 결과도 성공한 응답 페이지를 기록해야 하며, 실패를 빈 정상 결과로 바꾸지 않는다.

조회 종료 시각이 시작보다 빠르거나 조회 중 원장 revision이 바뀌면 해소할 수 없다. 조회 종료 revision, 해소 검토 revision, 현재 원장 revision도 일치해야 한다. 조회 확인 관리량과 해소 사실의 관리량을 비교한 뒤 기존 원장 수량·주문 미확정·충돌 검사를 수행한다.

페이지 누락·중복·오류·미완료·원장 변경은 QUERY_EVIDENCE_INCOMPLETE, 조회 수량과 해소 수량의 차이는 QUERY_QUANTITY_MISMATCH로 거절한다. 원장에 부분 해소를 남기거나 보유량을 조정하지 않는다. 완전한 근거는 해소 사실·outbox와 함께 보존된다.

## 범위와 이전 가상 데이터

실제 키움 조회를 실행하거나 서버의 동일 시점 스냅샷을 보장하는 기능은 아니다. 예상 페이지 수·마지막 응답·오류·원장 경계를 신뢰성 있게 수집하는 어댑터는 미구현이다. 조회 후 지연 이벤트는 기존 원장 검사와 후속 대조로 처리해야 하며, 이번 모델만으로 지연 이벤트의 부재가 증명되지는 않는다.

RECONCILED에 query가 필수가 됐다. 이전 임시 가상 DB에 query 없는 해소 사실이 있으면 현재 모델로 읽을 수 없다. 이를 자동으로 완전한 근거로 승격하거나 운영 DB에 마이그레이션하지 않는다. 과거 실험 DB는 보존하고 새 임시 DB로 시나리오를 재실행한다. 운영 저장소 전환·마이그레이션 정책은 별도 구현 대상이다.

불완전한 조회 시도 자체를 별도 실패 원문 원장으로 수집하는 기능은 아직 없다. 현재는 해소 입력을 거절하고 기존 차단 상태를 유지한다. 실제 원문 보관·민감정보 제거·인증·권한 정책도 후속 작업이다.

## 확인 결과

- 신규 6개 포함 전체 pytest **98개 통과, 7.99초**.
- 페이지 누락·중복·오류·미완료·조회 중 원장 변경 차단 및 완전한 조회의 해소 허용을 검사했다. 기존 대조·격리·요청·예약 검사도 통과했다.
- Ruff ALL·basedpyright 오류/경고 0. 포맷 및 코드 규칙 35개 파일 통과.
- 별도 임시 DB 직접 실행에서 누락 페이지 QUERY_EVIDENCE_INCOMPLETE, 차단 유지 True, 완전한 조회 수락 True, DB 재로드 후 관리량 100·차단 False, 중복 재수신 변화 False를 확인했다.
- 앞선 실행 일부는 도구 제한시간을 초과했다. 최종 재실행의 정상 종료와 전체 통과를 확인했으며 실행 지연의 원인까지 해결했다고 주장하지 않는다.

증권사 주문·조회 API, 배포, 운영 DB 변경은 수행하지 않았다. 다음 개발은 외부 명령 인증·권한 계약과 실제 패턴 상세 설정이다. 실제 계좌 연동 전 조회 어댑터·페이지 규격·고유 체결 식별과 원문 보관 정책을 별도로 검증해야 한다.
