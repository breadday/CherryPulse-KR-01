# D03 가상 손절 보호 진행 기록

## 취소된 손절 매도의 자동 재제출 차단

손절 매도 의무의 기존 요청이 취소 완료되어 예약이 풀려도, 정규장
dispatcher 호출이나 재시작 후 같은 발동을 근거로 잔량을 자동 제출하지
않도록 했다. 의무 조회는 `REVIEW_REQUIRED` / `REVIEW_AND_ALERT`, 확인된
미체결 수량과 해제된 예약량을 표시하며 운영자 검토 전에는 새 매도를
생성하지 않는다. 취소 확인은 손절 의무의 충족을 의미하지 않는다.

가상 SQLite 검사에서 손절 매도 전량 취소 후 의무 잔량·예약량, 재차
dispatcher 호출과 새 dispatcher 재시작 모두 추가 제출이 없는지 확인했다.
Python 3.10.8 32비트에서 관련 테스트 **13 passed**, 전체 pytest **156
passed**, Ruff 검사·포맷 확인, 가상 데모와 `git diff --check`가 통과했다.
이는 로컬 가상 검사이며 실제 증권사 조회, 알림, 취소 후 운영 정책 연결은
구현하지 않았다.

## 후속 검증: 실패 사유 조회

`virtual_stop_obligations` 결과에 `failure_reason`을 추가했다. 증권사 거절
또는 명시적 전송 실패가 원장에 기록되어 `REVIEW_REQUIRED`인 경우에만
해당 요청의 실제 기록된 사유를 읽는다. 근거가 충돌해 `BLOCKED_EVIDENCE`이면
사유를 임의로 고르지 않는다. 가상 거절은 전송 시도 기록 뒤에만 받아들이는
원장의 규칙에 맞춰 시험했다. Linux 임시 fixture 관련 pytest **12 passed**,
Ruff 및 `git diff --check` 통과. 실제 알림 전송과 증권사 상태 조회는
아직 연결하지 않았다.

## 2026-09-24 주문 실패 대응 정책 반영

사용자는 손절 시장가 매도가 거절되거나 전송 실패한 경우 자동 재주문을 멈추고,
증권사 상태를 조회한 뒤 남은 수량과 사유를 알리는 정책(1번)을 선택했다.
기존 가상 dispatcher의 동일 종목 매도 실패·거절 후 자동 재주문 차단을
재시작 포함 테스트로 확인했다. `StopObligationView.next_action`은 완료 시
`NONE`, 확인이 필요한 실패·거절·취소 시 `REVIEW_AND_ALERT`, 그 밖의
미완료·증거 불확실 상태에서 `QUERY_BROKER`를 반환한다. 이는 조회 전용
표시이며 실제 증권사 조회나 알림 전송을 실행하지 않는다. 부분체결 2주와
남은 2주, 명시적 미전송 실패 후 남은 2주를 각각 검사했다.

Linux Python 3.12 임시 Windows 잠금 대체 fixture의 관련 pytest
**11 passed**, Ruff 및 `git diff --check` 통과. Windows 3.10 32비트
전체 검사, 키움 주문·체결 조회 연동, 사용자 알림 경로 및 미체결 판단
시간은 아직 검증·구현하지 않았다. 기존 보유는 확인된 원가·수량·규칙의
인계 정책이 정해질 때까지 가상 보호 대상에 편입하지 않는다.

## 후속 검증: 의무 상태 조회

`Ledger.virtual_stop_obligations(symbol)`은 의무별 원래 수량, 확인된 매도
체결량, 남은 수량, 현재 예약량과 상태를 원장 사실에서 읽는다. 부분체결
중에는 `PENDING`, 모두 확인되면 `FULFILLED`, 증거 충돌·재대조·매도

`REVIEW_REQUIRED`로 표시한다. 이 조회는 새 매도 주문이나 자동 재시도를
생성하지 않는다. Linux 임시 fixture에서 관련 pytest **10 passed**,
Ruff와 `git diff --check` 통과. Windows 3.10 32비트 전체 회귀·키움
자료 검증은 수행하지 않았다. 의무 상태를 운영 주문 정책과 연결하는 작업은
아직 남았다.

## 후속 검증: 요청별 청산 의무 기록

가상 손절 매도 요청을 원장에 새로 수락할 때 `StopSellObligation`을 같은 SQLite
트랜잭션에 한 건 기록한다. 요청 ID, 주문 ID, 종목, 보호 수량, 발동 규칙 버전을
고정하며 동일 요청 재처리에서는 새 의무를 만들지 않는다. 기존 부분체결로
예약 중인 수량에는 추가 의무를 만들지 않고, 늦은 매수 체결로 새로 생긴
보호 수량만 별도 요청·의무로 기록한다. 매도 부분체결 뒤에도 원래 의무의
요청 ID와 최초 보호 수량은 보존된다. 기존 원장 테이블의 범용 journal에
새 이벤트 종류를 기록하므로 이 작업에서 운영 DB를 이전하지 않았다.

변경 파일: `execution/models.py`, `execution/storage.py`, `execution/ledger.py`,
`tests/test_virtual_stop_binding.py`. Linux Python 3.12의 임시 Windows 잠금
대체 fixture에서 관련 pytest **10 passed**, Ruff와 `git diff --check` 통과.
이는 Windows 계좌 잠금이나 전체 회귀 검사가 아니다. 청산 의무의 동적
잔량·완료·취소·거절 상태와 증권사 조회 근거 연결은 후속 단계이며 실제
주문 가능 상태를 뜻하지 않는다.

## 2026-09-24 후속 변경: 가상 매도 요청의 손절 발동 연결

`New.stop_latch_version`을 선택적 양의 정수로 추가했다. 가상 손절 dispatcher는
시장가 매도 요청에 실제 원장에 저장된 손절 발동의 규칙 버전을 기록한다.
`Ledger.submit`은 같은 종목·규칙 버전의 발동 기록이 없으면
`STOP_LATCH_LINK_NOT_FOUND`로 요청 전체를 거절한다. 매수와 지정가 주문에
손절 발동 버전을 붙이는 것도 거절한다. `virtual-stop:` 요청 키에 연결
버전이 빠지거나, 연결 버전에 손절 요청 키가 없을 때도 거절한다. 따라서 재시작 후 `Request`의 종목,
수량, 주문 ID, `stop_latch_version`을 발동 사실과 대조할 수 있다. 기존의
버전 표시가 없는 요청은 마이그레이션 없이 그대로 읽지만, 연결 근거가
있는 신규 손절 요청으로 소급 해석하지 않는다.

변경 파일: `execution/models.py`, `execution/ledger.py`, `execution/virtual.py`,
`tests/test_virtual_stop_binding.py`. Linux Python 3.12에서 Windows 계좌 잠금
대신 임시 fixture를 쓴 관련 pytest **9 passed**, Ruff 및 `git diff --check`
통과. Windows 잠금과 전체 회귀는 아직 미실행이다. 이 연결은 가상 손절
매도 요청과 발동 기록의 **추적 근거**이며, 독립된 청산 의무의 생성·완료
원장이나 자동 시세 감시·실제 거래 세션 증거는 아니다. 각 추가 매수 체결에
대한 별도 청산 의무와 요청 간 1:1 대조는 후속 구현이 필요하다.

- 기준: `main`의 D01 계약과 `docs/NEXT-DEVELOPMENT-PLAN.md`
- 상태: **부분 구현**. 규칙 저장·부분체결 연결·가상 보호 후보 계산, 고정 가격·원가 비율 손절 발동 기록, 정규장 가상 시장가 매도 예약과 dispatcher 인계를 검증했다. 자동 시세 수신·실제 세션 판정·증권사 주문 연결은 미완료다.

## 이번 범위

사용자 확정 정책(2026-09-24): 최근 체결가가 **수신 시각 기준 2초 이내**인 경우만 손절 판정에 사용한다. 지연 허용값으로 3초 이상을 입력하면 계약에서 거절한다. 기존 보유의 원가 또는 부분 매도 후 잔여 원가가 확인되지 않으면 **새 비율 손절 발동을 차단**한다. 이미 적법하게 발동한 규칙의 남은 보유 보호는 유지한다. 가상 손절 매도 제출은 정규장에 한한다. 거절·실패 후 자동 재주문은 금지한다. 실제 세션 판정과 미체결 판단 시간은 아직 미정이다.

`contracts/stop_evaluation.py`는 확인된 보유 수량, 손절 관측, 기존 매도 예약, 미확정 매도 및 재대조 상태에서 **추가 보호 후보 수량**을 계산한다. 부분 매수 체결 4주에는 4주 후보, 4주 매도 예약 뒤에는 0주, 추가 매수 체결로 7주가 되면 3주 후보를 반환한다. 평가 당시 보유 수량과 원장 보유 수량이 다르면 차단한다. 매도 결과가 `UNKNOWN`이거나 재시작 후 대조가 필요하면 추가 후보는 0주로 차단한다. 이 결과는 주문 의도가 아니며 주문 전송 권한도 아니다.

사용자 결정: 손절 시세는 **최근 체결가**, 평균 매수가는 **확인된 매수 체결가의 수량 가중평균(수수료 제외)**, 첫 가상 손절 주문은 **시장가 우선**이다. 시세 모델은 최근 체결가만 받으며, 평균 계산은 비유한 가격과 빈 체결 목록을 거절한다. `execution.facts.Fill`에 선택적 정확한 체결 가격을 추가했다. 기존 가격 없는 사실은 그대로 읽되, 가격이 하나라도 없는 매수 주문의 평균은 알 수 없음(`None`)으로 남긴다. 여러 주문의 가격이 모두 확인되고 동일한 보호 규칙 버전이 붙어 있으며 기존 보유 수량·매도 체결·수량 불일치가 없을 때만 `confirmed_stop_cost_basis`가 보유분 가중평균을 계산한다. 매도 체결 후의 평균과 이전 보유의 원가는 아직 근거가 없어 `None`으로 남긴다. 시장가 손절 주문도 아직 생성하지 않는다.

## 검증

2026-09-24 발동 유지 정책: `latch_virtual_price_stop`과 `latch_virtual_cost_stop`은 확인된 보유·규칙 버전·2초 이내 시세(비율 규칙은 확인된 체결 원가까지)로 발동 사실을 종목별 한 번 기록한다. 중복 호출과 재시작은 같은 기록을 읽는다. `virtual_latched_stop_candidate`는 남은 수량과 매도 예약을 다시 계산해 늦은 매수 체결도 포함한다. 신규 매수 제출과 미전송 매수의 가상 전송을 차단하며 매도 `UNKNOWN` 또는 재대조 필요 상태에서는 추가 후보를 차단한다. `VirtualDispatcher.drain_virtual_stop`은 호출자가 정규장이라고 지정할 때만 후보를 시장가 DAY 매도로 원장에 예약하고 가상 전송한다. 같은 수량의 중복 예약은 원장의 제출 검증이 차단한다. 기존 전체 청산 스위치가 켜져 있으면 그 경로가 매도를 담당한다. 매도 실패·거절은 자동 재시도하지 않는다. **세션 값은 호출자의 주장일 뿐 거래소 시간의 검증 근거가 아니며, 자동 감시와 실제 주문 API는 연결되지 않았다.** 발동 기록과 예약된 매도를 별도의 사실로 보존한다. Linux 임시 fixture의 관련 검사 **28 passed**, Ruff 통과. Windows 전체 회귀는 미실행이다.

2026-09-24 추가 작업: `virtual_cost_stop_candidate`는 원장 한 번 읽기에서 비율 손절 판정과 관리 수량·기존 매도 예약을 합쳐 추가 보호 후보를 반환한다. `virtual_price_stop_candidate`는 가격 없는 매수 체결에도 배정된 고정 가격 손절 규칙과 실제 보유 수량을 사용한다. 확인된 부분 매도 후에도 동일 규칙 버전의 잔여 보유만 평가하고, 서로 다른 규칙 버전·기존 보유·수량 불일치에서는 보류한다. `UNKNOWN` 매도와 재대조 필요 상태는 `SELL_EVIDENCE_UNRESOLVED`로 차단하고 오래된 시세는 후보를 만들지 않는다. 이 두 API는 **주문 의도나 보호 의무를 생성하지 않는 조회 전용 결과**다. Linux 임시 fixture에서 관련 계약·원장 검사 **26 passed**, Ruff 통과. Windows 파일 잠금·전체 회귀·실제 키움 검증은 미실행이다.

후속 로컬 작업: `Ledger.observe_virtual_cost_stop`은 재시작 후 원장에서 확인된 비용 근거와 매수 체결에 배정된 비율 손절 버전을 연결한다. 신선한 최근 체결가가 역치 이하일 때만 `TRIGGERED`를 반환한다. 가격 누락·기존 보유·매도 체결 시 `COST_EVIDENCE_INCOMPLETE`, 시세 지연 시 `QUOTE_NOT_FRESH`를 반환한다. 이는 가상 판정이며 청산 의무·주문은 생성하지 않는다. Linux 임시 fixture의 관련 6개 검사와 Ruff가 통과했다. Windows 전체 검사는 실행하지 않았다.

확인된 가상 매수 `Fill`이 원장에 반영될 때, 그 주문의 `config_version`에 해당하는 규칙이 있으면 같은 SQLite 트랜잭션에 `StopRuleAssignment`를 기록한다. 키는 체결 이벤트 ID이며 체결 수량과 규칙 버전을 보존한다. 중복 체결은 원장 멱등 처리로 재기록되지 않는다. 나중에 현재 설정 버전이 바뀌어도 이미 접수된 매수 주문의 체결은 주문 당시 규칙 버전으로 연결한다. 규칙이 없던 기존 주문의 체결은 임의의 규칙을 붙이지 않는다. 이 기록은 청산 주문 의무나 감시 활성화가 아니다. 평균 매수가 비율 손절은 체결 가격 근거가 여전히 없어 실제 평가·실행을 차단한다.
