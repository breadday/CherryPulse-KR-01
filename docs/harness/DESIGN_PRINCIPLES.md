# 설계 원칙

이 프로젝트는 한국 주식 자동매매를 실전처럼 검증하기 위한 프로그램이다. 현재 운영 기준은 `RUN_MODE=live`와 키움 모의투자 계좌이며, 주문 경로는 실계좌 실매매와 같은 수준으로 엄격하게 다룬다.

## 1. 매매 철학

- 기본 방향은 일봉 후보 기반 스윙 매매다.
- 장중 조건검색과 틱 단타는 기본 매매 축이 아니라 보조 또는 연구 대상으로 둔다.
- 종목 선정은 장마감 후 또는 장 시작 전에 일봉 데이터로 수행한다.
- 다음날 장중에는 전날 선정된 후보만 감시하고, 과열/급락/갭 과다 같은 실행 제외 조건만 확인한다.
- 전략은 독립 후보, 독립 진입, 독립 청산, 독립 성과를 가져야 한다.

## 2. 현재 활성 운영 구조

- `build_daily_strategy_snapshot.py`가 일봉 CSV를 읽어 `condition_snapshot.json` 후보 파일을 만든다.
- `main_live.py`는 `condition_snapshot.json`의 후보만 실시간 감시한다.
- `ENABLE_CONDITION_SEARCH = False`가 기본이다.
- `momentum`, `vcp_box`는 기본 비활성이다.
- 활성 실전형 후보 전략은 `bottom_reversal`, `leader_pullback`, `close_buy`다.

## 3. 실전형 모의투자 원칙

- 모의투자 계좌라도 주문 경로는 실주문 경로처럼 취급한다.
- 계좌가 실계좌로 바뀌면 실제 주문이 발생할 수 있다.
- 실행 전 계좌번호와 키움 접속 환경을 확인한다.
- 주문 차단, 중복매수 방지, 보유종목 감시, 미체결 관리, timeout, 자동종료는 실계좌 수준으로 유지한다.

## 4. 전략 추가 원칙

새 전략은 다음 순서를 지켜야 한다.

1. 전략 아이디어를 문서화한다.
2. 일봉 후보 생성 로직을 만든다.
3. 백테스트 또는 과거 데이터 검증을 수행한다.
4. 모의투자 로그로 며칠 이상 관찰한다.
5. 기대값과 리스크가 확인된 뒤에만 실전형 후보에 편입한다.

## 5. 전략 통과 기준

- 최소 거래수 30회 이상을 우선 기준으로 한다.
- 기대값이 양수여야 한다.
- 손익비 또는 profit factor는 1.5 이상을 목표로 한다.
- 특정 한두 종목의 큰 수익에만 의존하면 실전 적용 후보로 보지 않는다.
- 손절 후 재진입, 과열 매수, 보유종목 누락 같은 운영 리스크가 없어야 한다.

## 6. 금지 원칙

- 일봉 전략을 만들면서 장중 틱 조건을 과도하게 섞지 않는다.
- 조건검색 결과를 모든 전략에 무차별로 흘려보내지 않는다.
- 전략별 후보와 성과를 분리하지 않은 상태로 새 전략을 추가하지 않는다.
- `QEventLoop`나 외부 API 호출을 timeout 없이 무기한 대기시키지 않는다.
- 한글 파일을 깨진 인코딩 상태로 방치하지 않는다.
