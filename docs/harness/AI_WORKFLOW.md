# AI 작업 절차

이 문서는 Codex, ChatGPT, 다른 AI 도구가 이 프로젝트를 수정할 때 따라야 할 절차다.

## 작업 전 읽을 문서

1. `docs/harness/DESIGN_PRINCIPLES.md`
2. `docs/harness/FILE_RESPONSIBILITY.md`
3. `docs/harness/CHANGE_CHECKLIST.md`

## 작업 순서

1. 사용자의 요청을 현재 매매 철학과 비교한다.
2. 수정할 파일의 책임 범위를 확인한다.
3. 기존 전략과 충돌하는 부분을 먼저 찾는다.
4. 필요한 최소 파일만 수정한다.
5. 문법 검사와 관련 검증 명령을 실행한다.
6. 로그로 완료 조건을 확인한다.
7. 사용자에게 변경 내용, 검증 결과, 남은 위험을 짧게 보고한다.

## AI가 하면 안 되는 일

- 설계 원칙을 확인하지 않고 전략을 새로 추가하지 않는다.
- 실시간 조건검색을 몰래 다시 켜지 않는다.
- 실전형 모의투자 주문 경로를 가볍게 취급하지 않는다.
- 사용자가 만든 변경을 되돌리지 않는다.
- 한글 깨짐이 있는 파일을 그대로 확장하지 않는다.
- timeout 없는 대기 루프를 만들지 않는다.

## 사용자 요청 템플릿

앞으로 큰 작업은 가능하면 아래 형식으로 요청한다.

```text
목표:
바꾸면 안 되는 것:
수정 가능 파일:
검증 방법:
완료 기준:
```

## AI 응답 기준

- 코드 수정이 필요한 요청이면 가능한 한 직접 수정한다.
- 큰 설계 변경이면 짧은 계획을 먼저 공유한다.
- 실전 주문 위험이 있으면 반드시 언급한다.
- 검증하지 못한 항목은 숨기지 않고 말한다.
