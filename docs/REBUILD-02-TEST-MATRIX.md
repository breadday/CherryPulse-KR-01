# REBUILD-02 테스트 매트릭스

2026-09-13. [계약](REBUILD-02-CONTRACTS.md)의 **문서 기대값**이다. 실제 엔진·API 테스트를 실행한 결과가 아니다. 원 지시서의 번호 9~20을 아래 T01~T12로 정규화했다.

## 공통 표기와 재생 규칙

각 사례는 독립된 계좌 A/모의 환경/종목 X/실행 E를 사용한다. 외부 보유는 별도 언급 없으면0, 계좌 원장 보유 H=관리량 M, 모든 초기 관리량은 명시 배정 또는 표의 기존 매수 체결에 근거한다. 가격은 모든 주문에서 지정가 `10000`원, 정정 가격은 명시한 경우만 다르다. 값은 API 매핑이 확인됐다고 가정한 내부 정규 이벤트이며 키움의 실제 전송 순서 보장이 아니다.

주문 표기 `Q0/D/F/C/A`는 최초/정정증감/누적체결/취소/활성잔량이다. B는 매수, S는 매도, R=RESERVED, L=잔여 청산 의무. 모든 수량은 주. 요청 N=신규, U=정정, K=취소이며 각 사례 접두어를 붙인 별도 UUID의 표시 별칭이다. 이벤트 ID도 표시 별칭으로 실제 UUID 고유 이벤트와 일대일 대응한다. 재수신은 같은 고유 ID를 유지한다.

API 횟수는 **시나리오 시작 이후 실제 호출 횟수**, 기존 제출 제외이며 `(신규, 정정, 취소)` 순서다. ACK는 해당 요청 접수, CONF는 효과 확인을 뜻한다. 제출 이벤트는 INTENT_PERSISTED→SENDING→SENT를 거친다. 매트릭스에서 수량이 확정된 신규 주문은 ACK까지 받은 것으로 명시한다.

각 사례 마지막에 모든 고유 이벤트를 다시 재생한다. 추가 체결·포지션·예약·의무 반영0, 추가 신규/정정/취소 호출 `(0,0,0)`이어야 한다. 감사용 중복 수신 로그는 허용한다. 같은 키·다른 내용은 재생해도 같은 충돌이다. 최종 합계 표는 주문별 수치와 계좌 수치를 분리한다.
