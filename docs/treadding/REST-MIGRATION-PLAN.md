# CherryPulse REST 전환·자동 개발 계획

결정일: 2026-10-14. 기준 main: `1ec7966`. 전환 브랜치: `refactor/kiwoom-rest`.
사용자는 계획·개발·테스트·검증·문서화·커밋·푸시·반영을 요청했다.
이 승인은 실계좌/모의계좌 주문 전송, 운영 DB 변경이나 비밀 키 공개를 포함하지 않는다.

## 목표와 범위

외부 입력 종목 → 기존 버전 패턴 → 인증된 설정 수락 → 시세 감시 → 주문·체결 → 보호 → 복구.
종목 추천·백테스트 승격은 복원하지 않는다. 화면이 닫혀도 실행 엔진이 감시한다.
최초 운영은 지정 Windows PC 한 대, 이후 클라우드는 별도 단계다.
REST는 조회·주문, WebSocket은 시세·체결을 담당한다. 주문 소유권은 단일 dispatcher다.

기존 SQLite 원장, 요청/주문 분리, UNKNOWN 재전송 금지, 수량 보존식,
Q12 매수(1주·10만원 상한·당일 1회·15:20 만료·-3% 보호), 일반 매도 수동 제출 정책을 유지한다.
OCX와 REST 원장 scope를 혼용하거나 virtual 대조 결과를 실제 계좌 근거로 승격하지 않는다.

## 공개 소스 채택 결정

공식 저장소: https://github.com/Kiwoom-Securities/Kiwoom-REST-API
조사 SHA: `953e5dbff123f437ab4d11a78a95191a685eb51f`.
확인: `kiwoom/core/client.py`, `types.py`, 계좌 예제 `get_domestic_unfilled_orders.py`,
`get_domestic_account_evaluation_balance.py`, `LICENSE.md`.
공식 라이선스는 수정·재배포 제한을 명시한다. MIT 소스로 간주해 복사·수정·vendoring하지 않는다.
따라서 지금은 공개 API 규격을 참고해 독립 경계를 작성하고, 공식 SDK 직접 의존 여부는
사용 조건·버전·재시도 정책 검토 후 결정한다. 구현 코드는 공식 소스 복제가 아니다.
`gejyn14/kiwoom-cli`는 비교·진단 후보이며 핵심 dispatcher로 채택하지 않는다.

공식 클라이언트에서 인증 오류 후 자동 재호출을 확인했다. 주문 경로는 동일한 재시도
정책을 무검토 적용하지 않는다. ACK는 체결도 취소 완료도 아니다.

R02/R03의 오프라인 개발은 키 없이 진행한다. 실제 API 근거는 계좌 연결 후 별도로 검증한다.
Q01~Q11의 의미는 유지하되 OCX 필드 증거를 REST 필드 증거로 대체해야 한다.
OCX FID 예약 결과는 참고 기록이며 REST 전환의 선행 조건이 아니다.

Python 버전·PyQt 의존성 제거는 imports와 Windows 회귀 확인 후 진행하며 이번에는 변경하지 않는다.

## 자동 개발 사이클과 중단 내구성

각 작업은 계획 → 작은 구현 → 관련 검사 → 검증 근거 → 미완료 기록 → 한글 커밋 → push 순서다.
각 단계 완료 시 `REST-MIGRATION-STATUS.json`과 `REST-MIGRATION-HANDOFF.md`를 갱신한다.
반나절짜리 변경을 한꺼번에 보관하지 않는다. 토큰 여유가 줄면 즉시 마지막 안정 단위를
커밋·push하고 진행 중 작업·실패 명령·다음 행동을 남긴다. 중단으로 파일이 남으면 다음 AI가
`git status`부터 조사하며 사용자 변경을 reset/stash/delete하지 않는다.

`python tools/verify_rest_migration.py`는 고정된 오프라인 검사를 자동 실행하고
`results/rest-migration-verification.json`을 원자적으로 갱신한다. 실패는 exit 1이다.
GitHub Actions는 push/PR 시 오프라인 검사와 Windows 원장 전체 회귀·데모를 자동 실행한다.
이는 개발자 AI를 무한 재실행하는 서비스가 아니다. 세션 종료·사용량 한도 후 개발 재개에는
다음 AI 실행이 필요하며 아래 인계 문서가 대화 기억을 대신한다. 자율 개발 데몬 설치는 미수행.

완료한 오프라인 단위는 전환 브랜치로 push한다. main 반영은 CI 확인 후 수행하며,
실주문 활성화·계좌 인계는 소프트웨어 병합과 분리한다. CI 실패를 숨기거나 강제 병합하지 않는다.

## 완료의 정의

소프트웨어 통과, 실제 증권사 읽기 통과, 허용된 모의 주문 통과, PC 무인 운영 통과,
웹/실기기 인수 통과를 각각 기록한다. 하나의 검사 개수로 전체 완료를 주장하지 않는다.
전체 완료 전 미구현·실증 대기 항목은 상태 문서에서 계속 열린 상태로 유지한다.
