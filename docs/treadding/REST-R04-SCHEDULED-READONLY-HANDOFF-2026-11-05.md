# CherryPulse 예약 작업·R04 읽기 전용 검증 인계 (2026-11-05)

## 예약 작업 PC 실측

세 기존 주문 가능 작업은 삭제하지 않고 `Disable-ScheduledTask`로 비활성화했다. Windows Task Scheduler 재조회 결과 `Enabled=false`, 상태 `Ready`(대기), 마지막 실행 시각과 결과는 아래와 같이 그대로 남아 있다.

| 작업 | Enabled | 마지막 실행 (KST) | 마지막 결과 |
|---|---:|---|---:|
| CherryPulse-paper-demo | false | 2026-11-05 09:03:01 | 1 |
| CherryPulsePaperDemo | false | 2026-11-05 09:10:01 | 1 |
| CherryPulse-R045-Demo | false | 2026-11-05 09:30:01 | 0 |

설정/XML과 실행 이력은 삭제하지 않았다. 세 작업의 다음 실행은 비활성 상태라 예정되지 않는다.

`CherryPulseFIDMorning`은 Enabled 상태이나 작업 action이 저장소 루트의 `run-fid-morning.bat`을 가리키고, 해당 경로가 현재 존재하지 않는다. Task Scheduler의 최근 결과는 1이다. legacy 보관 경로의 동명 BAT은 사용자 로그인 후 `tools\inspect_kiwoom_realtime.py 005930 --start-at 09:05 --seconds 120`만 실행하며, 파일 주석·명령에는 주문/취소/TR 조회가 없다. 다만 실행 대상 경로 자체가 없어 실제 action과 legacy 파일이 동일하다고 단정할 수 없다. 기존 예약 설정은 추가 변경하지 않았다. 기능 재개 전 action 경로를 사용자 확인 후 점검한다.

## 2026-10-28 R04 기록 (파일 근거)

`results/r045-20261028/manifest.json` 및 관련 결과를 확인했다.

- 장중 WebSocket 시세 수신: **확인** (연결 1, 274건, 프레임 오류 0, 장 마감 전 신선도 true, 저장 true)
- 조회 5건 상세 결과: **확인 불가** (manifest에는 요약 출력 바이트 수만 있음)
- 주문 접수: **ACKED** (`results/paper-buy-20261028.json`에 모의 1주 접수 상태가 기록됨)
- 체결 및 주문 이력 연결: **미확인** (`LINKAGE_UNCONFIRMED`, 단계 종료 코드 1)
- 실행 시각과 커밋 SHA: **미확인**

`ACKED`는 주문 접수 확인이지 체결 확인이 아니며 현재 미체결 여부도 뜻하지 않는다. 계좌의 당일/현재 상태는 이 저장소 결과만으로 판단할 수 없다. 자동 주문·취소·재전송은 하지 않았다.

### HTS에서 사람이 확인할 절차

영웅문4에서 계좌와 해당 날짜를 선택해 다음 화면을 각각 조회한다. 조회만 하고 정정/취소/주문 버튼은 누르지 않는다.

1. **[0351] 금일주문체결내역** 또는 **[0343] 기간별 주문체결상세**에서 2026-10-28 주문과 체결 수량/상태를 확인한다.
2. **[0342] 원장미체결(당일)** 또는 **[0341] 실시간 미체결**에서 현재 미체결을 별도로 확인한다. 미체결 수량이 없다는 현재 결과는 10월 28일 체결 사실을 단독 입증하지 않는다.
3. **[0309] 실시간 잔고/미체결**에서 잔고 변화를 보조 대조한다. 종목·수량·날짜·주문 상태를 저장소 결과와 비교하되, 채팅이나 문서에 계좌/주문 식별값을 올리지 않는다.

키움 공식 도움말: [0309 실시간 잔고/미체결](https://download.kiwoom.com/hero4_help_new/0309.htm), [0342 원장미체결(당일)](https://download.kiwoom.com/hero4_help_new/0342.htm), [0352 전일체결내역](https://download.kiwoom.com/hero4_help_new/0352.htm). 메뉴 번호는 프로그램 버전에 따라 다를 수 있다.

## 이후 예약 실행 결과

예약 스크립트를 실행하지 않고 `results/r045-YYYYMMDD/manifest.json`만 읽었다. `QUOTE_WS` 단계는 10/29: 360건, 10/30: 28건, 11/02: 22건, 11/03: 14건, 11/04: 6건, 11/05: 21건으로 기록됐고 각 manifest에서 종료 코드 0, 오류 프레임 0, 장 마감 전 신선도 true다. 이는 과거 장중 WS 증거이지, 재검증이나 현재 주문 상태 확인은 아니다.

10/30~11/05 manifest에 `ORDER_SUBMIT` 코드 1 / `SECOND_ORDER_BLOCKED` 기록이 있다. 이는 두 번째 요청 차단 증거일 뿐 어떤 이전 요청이 접수·체결됐는지는 설명하지 않는다. 어느 날짜도 이 문서만으로 주문/체결/현재 미체결을 단정하지 않는다. 이 문서 작성 과정에서 그 실행기를 호출하지 않았다.

## R04 읽기 전용 장중 자동 검증 준비

새 모듈 `tools/r04_readonly_morning_run.py`는 기존 주문 예약과 별개다. 평일 09:10 KST에 Task Scheduler로 하루 한 번 실행되도록 등록하는 방안이다. PC를 켜 두고 로그인/네트워크 준비 상태를 유지하면 실행 결과는 `results/r04-readonly-YYYYMMDD.json`에 저장돼 퇴근 후 확인할 수 있다. 구현에는 제한된 5개 읽기 조회와 30초 시세 구독만 고정돼 있고 주문 제출/정정/취소 호출은 없다. query 원문/행/시세 payload/계정·토큰은 결과 파일에 쓰지 않으며 allowlist 필드만 남긴다.

- 장외/주말/개장 전이면 네트워크를 호출하지 않고 `SKIPPED_OUTSIDE_MARKET`로 저장한다. 장중인데 조회나 실시간 시세 검증이 불완전하면 `INCOMPLETE`로 저장한다.
- 주문 OFF, 계좌 미대조 표식을 계속 유지한다. R04 실계좌 식별/원장 연결을 완료했다고 판정하지 않는다.
- 새 예약은 **제안만** 했고 아직 Windows에 등록하지 않았다. 등록 전 실제 파일/명령과 Task Scheduler 정책을 검토하고 사용자 확인을 받는다. 기존 주문 예약과 병행 등록하지 않는다.
- 첫 운용 전에는 사용자 승인하에 실행 일정을 등록한 뒤, 테스트는 정규장 내의 읽기 전용 세션에서만 하고 결과의 비밀/계좌 정보를 확인해 마스킹한다.

## 미결/차단 사항

- 10/28 및 이후 ACKED/주문 결과의 브로커 원장, 체결 여부, 현재 미체결: HTS 사용자 확인 필요.
- `CherryPulseFIDMorning` action의 실제 BAT 경로 부재와 legacy 파일 동일성: 미확인.
- 자동 R04 신규 예약: 미등록. 이 저장소 변경은 예약 설정을 추가로 바꾸지 않았다.
- 기존 R045 결과는 관측 산출물이며 계좌 identity mapping 및 R04 원장 linkage를 입증하지 않는다. R05 주문 실증은 계속 보류.
