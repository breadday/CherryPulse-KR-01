# OpenCode 자동 개발 지시서

갱신일: 2026-10-27  
대상 저장소: `CherryPulse-KR-01`  
목적: OpenCode가 작업 상태를 먼저 파악하고, 확인된 범위의 개발·검증·기록을 독립적으로 이어가게 한다.

이 문서는 OpenCode에 아래 **「실행 프롬프트」 전체를 붙여넣어** 사용한다. 저장소의 `AGENTS.md`와 최신 사용자의 직접 지시는 이 문서보다 우선한다.

## 실행 프롬프트

```text
이 저장소에서 CherryPulse-KR-01의 진행 중인 개발을 이어서 수행해. 단순 현황 보고에서 멈추지 말고, 확인된 상태를 바탕으로 지금 가능한 다음 개발 단위를 구현하고 검증한 뒤 문서에 인계해.

## 시작 전 확인

1. 저장소 루트 `AGENTS.md`를 읽고, 아래 문서를 순서대로 읽어 현재 결정과 작업 경계를 파악해.
   - `docs/treadding/REST-MIGRATION-PLAN.md`
   - `docs/treadding/REST-MIGRATION-HANDOFF.md`
   - `docs/treadding/REST-MIGRATION-STATUS.json`
   - `docs/CherryPulse-KR-01-Development-Direction.md`
   - `docs/CherryPulse-KR-01-Rebuild-Plan.md`
   - `docs/REBUILD-02-CONTRACTS.md`
   - `docs/REBUILD-02-TEST-MATRIX.md`
   - `docs/REBUILD-02-OPEN-QUESTIONS.md`
   - `docs/treadding/DEVELOPMENT-READY-AND-BLOCKERS.md`
   - 작업 대상과 관련된 최신 검증·인수 문서
2. `git status --short --branch`, `git branch --show-current`, `git log -5 --oneline`으로 기준을 확인해. 이 작업을 시작할 때 이미 존재하는 수정 파일은 사용자 작업으로 간주하고 내용을 먼저 살펴봐. `reset`, `clean`, `stash`, 무단 checkout, 덮어쓰기, 삭제, 되돌리기를 하지 마.
3. 원격 최신화가 필요하면 로컬 수정사항을 보존하는 방식으로 fetch와 divergence만 확인해. 브랜치를 바꾸거나 만들기 전에 기존 브랜치·작업트리 상태를 확인하고, 로컬 수정이 있으면 그 수정과 충돌하지 않는 범위에서 진행해.
4. 문서 상태와 실제 코드/검증 결과가 다르면 불일치를 먼저 기록하고, 오래된 상태값을 사실처럼 이어받지 마.

## 현재 기준점과 우선 작업

- 진행 보드는 R00–R08이며 상태 파일과 인계 문서가 최신 판정 원본이다. 상태를 임의 승격하지 마.
- 현재 기록상 R04 실제 모의계좌 식별·이력 근거, WebSocket 장중 시세 수신이 미완료다. R045 최근 manifest는 사전 조회 성공, WebSocket CONNECT의 `DEPENDENCY_ERROR`, 시세 0, 주문 단계 미진입이다. 현재 호스트에서 `CherryPulse-R045-Demo`와 Python 3.10을 찾지 못했다. 이 호스트가 지정 PC라고 추정하지 마.
- 첫 번째 행동은 지정 PC 실행이 필요한 외부 차단만 반복 안내하는 것이 아니라, `external_pending`을 대조해 현 저장소에서 독립적으로 완료할 수 있는 다음 소프트웨어 작업을 찾아 구현하는 것이다. 단, 실제 API 응답, 주문 결과, 클라우드 계약, 사용자 PIN/실기기 결과를 추정해야만 진행되는 작업은 임의 구현하지 말고 계약/증거를 기다려.
- R04 계좌 실증 전에 R05 dispatcher, R06 실제 보호 연결, R07 무인 실주문 흐름을 활성화하지 마. 계약에 따라 안전하게 가능한 오프라인 테스트, 고정된 실패 진단, 문서 명확화, 기존 기능 회귀는 진행할 수 있다.
- 보드 API는 `docs/api/BOARD-API-HANDOFF.md`의 제안 초안일 뿐 실제 서버 계약이 아니다. `.invalid` 호스트, 추측 인증, 가짜 운영 데이터 또는 인터넷에 노출되는 임시 API를 제품 구현으로 만들지 마.

## 기술·제품 경계

- REST/HTTP/WebSocket 프로브는 32비트 전용이 아니다. 저장소 Python 기준은 `>=3.10.8,<3.11`이며 아키텍처 지정이 없다. 32비트 요구는 기존 Kiwoom ActiveX/COM 경로에만 해당한다. R045는 `py -3.10` 및 같은 인터프리터의 `tools/requirements-rest-probes.txt`를 기준으로 한다. 임의 호스트에 Python을 설치하거나 32비트 설치를 지시하기 전에 해당 호스트와 목적을 확인해.
- 제품은 사용자가 외부에서 찾은 종목을 등록하고 기존 매수·매도 패턴을 연결하는 보드다. 내부 종목 발굴·추천·점수화·백테스트 승격·자동 후보 편입 기능을 새로 만들거나 복원하지 마. `back/`은 보관 자료이며 활성 경로에서 import하거나 배치를 실행하지 마.
- 기존 주문 안전장치(중복 주문 방지, UNKNOWN 재전송 금지, 체결·수량 대조, 손절, 재시작 복구)를 약화하거나 우회하지 마. `execution.models.Scope`의 virtual 제한을 문자열 변경만으로 실제 REST scope로 풀지 마.
- `orders_enabled`는 항상 `false`로 유지한다. 실제 주문 API는 모의 계좌에서도 호출될 수 있다. 주문 제출·취소·실행 모드 변경, 예약 주문 runner 실행/활성화/변경, `main_live.py`, 배포, 운영 DB 변경은 이 프롬프트의 허가에 포함되지 않는다. 별도의 직접적이고 구체적인 사용자 요청 없이는 실행하지 마.
- `.env`, 키/secret, access token, 계좌번호, 원문 브로커 응답, 운영 DB 및 주문번호를 출력하거나 문서/로그/테스트 산출물에 복사하지 마. 키 값은 묻지 말고 런타임 환경변수에서만 사용해.
- 사용자의 기존 변경과 비밀자료를 보존해. 가짜/합성 fixture는 합성이라고 표시하고 실제 증권사 증거로 승격하지 마.

## 반복 작업 방식

1. 상태 JSON의 첫 미완료 작업, 명시된 gate와 현재 코드 증거를 비교해 가장 작은 독립 작업 하나를 선택한다. 먼저 `current_task`와 작업 상태를 `in_progress`로 갱신하고, HANDOFF에 의도와 완료 기준을 적는다.
2. 영향 파일과 계약을 읽고, 필요하면 구현 전에 짧은 계획과 위험을 작업 설명에 남긴다. 공개 API의 누락된 의미, 필드, endpoint를 추측하지 않는다.
3. 코드·문서·회귀 검사를 한 작은 단위로 변경한다. 검사는 작업과 저장소 지침에 맞는 범위에서 실행한다. 전체 검증 명령은 `python tools/verify_rest_migration.py`; 프로젝트 설정에 따른 테스트/lint/type 검사도 수행하되 현재 호스트에서 지원하지 않는 Windows/증권사/기기 검사를 성공으로 표시하지 않는다.
4. 실행한 모든 검증의 정확한 명령, 종료 코드, 통과/실패 수를 적는다. 기존 baseline 문제와 새 회귀를 구분하고, 결과가 없는 항목은 `미실행` 또는 `미확인`으로 둔다. `git diff --check`와 마지막 `git status --short --branch`도 확인한다.
5. 각 의미 있는 단계가 끝날 때 `REST-MIGRATION-STATUS.json`과 `REST-MIGRATION-HANDOFF.md`를 실제 증거에 맞게 갱신한다. `orders_enabled: false`와 외부 차단 항목을 유지하고, 실패 명령·바뀐 파일·다음의 구체적인 행동을 기록한다. JSON은 파싱 가능해야 한다.
6. 자동화는 OpenCode가 실행 중인 동안 독립적으로 가능한 작업을 이어가는 것을 뜻한다. 무한 실행 데몬이나 재귀 에이전트, 예약 작업을 만들지 마. 세션 한도·사용자 입력·외부 PC/API/승인 때문에 멈출 때는 완료한 작업을 기록하고 정확한 재개 명령과 필요한 외부 증거만 인계한다. 외부 대기를 이유로 독립적인 오프라인 일을 건너뛰지 마.

## 완료·Git 정책

- 소프트웨어 검사, Windows 엔진 회귀, 증권사 조회, 허용된 모의 주문, 배포, 브라우저/모바일 인수는 별도 결과로 기록한다. 한 종류의 성공으로 다른 종류를 완료 처리하지 마.
- R04 완료에는 체크리스트에서 정한 조회들의 실제 모의계좌 완전성·식별 근거와 장중 WebSocket fresh quote 증거가 필요하다. R05는 별도 명시 승인 및 HTS 사후 확인 전에는 진행 완료로 올리지 않는다. R08은 보드 소프트웨어 검사와 실제 운영/기기 인수를 구분한다.
- 현재 `AGENTS.md` 지침에 따라 사용자 변경을 보존하고 커밋·push는 사용자가 별도로 요청할 때만 한다. 이 지시서 자체는 커밋·push 허가가 아니다. 브랜치 변경, PR 병합, 운영 배포도 자동 허가가 아니다. CI를 조회할 수 있으면 결과를 기록하되 코드 완료와 배포 완료를 혼동하지 않는다.
- 다음 AI/사용자가 같은 상태를 다시 조사하지 않도록 HANDOFF와 상태 JSON을 유지한다. 문서에 검증하지 않은 완료 주장을 남기지 마.
```

## 현재 재개 지점

지시서를 작성한 시점의 상태 JSON은 R04를 현재 작업으로 지정하고 있다. 최근 기록은
R045 WebSocket 연결이 의존성 오류로 시작되지 않아 시세 수신이 0이고 주문 단계에
진입하지 않은 상태다. 현재 호스트에서 지정 PC의 예약 작업이나 Python 3.10 런타임을
확인하지 못했으므로, 특정 PC 설치·실행 결과를 만들어내지 않는다. OpenCode는 위 지침에
따라 로컬에서 가능한 개발 단위를 우선 조사하고, PC 실증은 사용자 PC에서 재현 가능한
검사 명령과 판정 조건을 인계한다.

R045의 핵심 실행 안내는 Python 3.10 계열 런타임이며 32비트 요건이 아니다. 실제
설치/의존성 확인은 예약 작업이 실행되는 지정 PC에서 그 작업의 Python 경로를 확인한 뒤
같은 인터프리터로 `python -m pip install -r tools/requirements-rest-probes.txt`를 실행한다.
계정 키는 환경변수에만 두며 지시서나 로그에 복사하지 않는다.
