# CherryPulse-KR-01 개발방향 — 보드 기반 패턴 트레이딩

- 작성일: 2026-09-11
- 버전: 1.0
- 상태: 사용자 요구사항을 반영한 개발 기준 문서
- 적용 대상: CherryPulse-KR-01
- 우선순위: 이 문서는 기존 `CherryPulse-KR-01-Vercel-Plan.md`의 전략 검증·후보 승인 중심 기능 계획을 대체한다. 충돌하는 내용은 본 문서를 따른다.
- 작성 범위: 개발방향 기록. 기존 소스의 삭제·개편·배포를 완료했다는 의미는 아니다.

## 1. 프로젝트 목적

**외부 사이트에서 찾은 종목을 사용자가 입력하고, 종목별 매수·매도 패턴을 설정하여 조건 감시와 주문 실행을 수행하는 트레이딩 시스템으로 개편한다. 모든 진행 상황은 웹 보드에서 확인하고 관리한다.**

이 프로젝트에서 종목을 발굴하거나 전략의 수익성·우수성을 검증하지 않는다. 사용자가 정한 매수 조건과 매도 조건을 정확히 감시하고 실행하는 것이 목적이다. 특히 손절은 조건 충족 시 추가 사용자 확인을 기다리지 않고 청산 주문을 처리하고 체결 결과까지 추적한다.

## 2. 확정된 개발 원칙

| 항목 | 개발 기준 |
|---|---|
| 종목 확보 | 사용자가 다른 사이트에서 종목을 찾아 코드·이름을 입력 |
| 주요 화면 | 상태별 보드, 종목 관리, 매수 패턴 관리, 매도 패턴 관리 |
| 매수 | 종목에 지정한 매수 패턴의 실행 조건이 충족되면 주문 |
| 매도 | 종목에 지정한 매도 패턴에 따라 주문. 손절을 우선 구현 |
| 손절 | 시세 감시 → 조건 감지 → 청산 주문 → 체결·미체결 추적 |
| 운영 기록 | 조건 충족 근거, 적용 패턴, 주문·체결·오류를 확인 |
| 웹 배포 | Vercel에서 웹 화면 사용 |
| 엔진 배치 | 기존 Windows/Python 실행 환경을 유지하는 방향 |
| 전략 평가 | 전략 검증·점수 평가·백테스트·성과에 따른 후보 승인 기능 제거 |

패턴의 ‘조건 충족 여부’는 매매 실행을 위한 판단이다. 과거 성과를 평가해 전략의 적합성을 승인하는 절차를 추가하지 않는다.

## 3. 제거 범위와 유지 범위

### 제거 대상

- 전략 성과·유효성 검증 실행과 이를 위한 화면·API·배치 작업.
- 전략 점수·등급·백테스트 결과를 근거로 매매 후보를 선별하는 흐름.
- 검증 통과 후 감시 후보로 승격·승인하는 절차.
- 내부 종목 발굴·추천·순위 산출 및 그 결과에 의존하는 자동 편입 흐름.
- 기존 계획의 검증 대시보드, 검증 결과 12개 묶음, 전략 검증 이력 중심 데이터 구조.

실제 제거 파일은 소스 의존성을 확인한 후 정한다. 선정·검증 로직과 주문 실행이 섞인 모듈은 역할을 분리하고, 공유 시세 수집·패턴 계산·주문 기능까지 일괄 삭제하지 않는다. 기존 전략에서 필요한 조건 계산이 있으면 성과 평가 경로를 제거하고 패턴 실행 기능으로 재구성한다.

### 유지·보강 대상

- 종목코드·주문 수량·패턴 입력 형식 확인.
- 실제 시세의 시각·연결 상태 확인.
- 중복 주문 방지, 잔고·보유 수량 확인, 주문 상태 관리.
- 부분체결·미체결·주문 거절·재접속·재시작 복구 처리.
- 보유 포지션의 손절 감시와 청산 처리.
- 위 동작을 확인하는 소프트웨어 테스트.

전략 검증 제거는 주문 실행의 오류 방지와 소프트웨어 테스트를 제거한다는 뜻이 아니다. 기존 RiskGuard의 신규 매수 제한이 보호 청산까지 막지 않는지도 개편 과정에서 확인한다.

## 4. 화면 구성

| 메뉴 | 목적 | 주요 기능 |
|---|---|---|
| 트레이딩 보드 | 종목의 현재 상태를 한눈에 파악 | 상태별 카드, 종목 검색, 필터, 종목 상세 열기 |
| 종목 관리 | 외부에서 찾은 종목을 등록·설정 | 추가·수정·보관, 메모·출처, 패턴 연결, 주문 금액·수량 설정 |
| 매수 패턴 관리 | 매수 실행 규칙 관리 | 패턴 생성·수정·복제·비활성화, 조건·주문 방식 설정 |
| 매도 패턴 관리 | 손절을 포함한 청산 규칙 관리 | 매도 조건, 손절 구분, 전량·부분 수량, 주문·미체결 처리 설정 |
| 주문·체결 기록 | 실행 결과와 문제 확인 | 발생 조건, 주문 상태, 체결 수량·가격, 거절·취소 사유 |
| 운영 상태 | 실제 감시 가능 상태 확인 | 엔진 연결, 시세 시각, 실행 모드, 설정 반영 결과 |

### 보드 구성안

보드의 열은 실제 엔진 상태를 기준으로 이동한다. 아래 상태 명칭은 구현 시 세부 상태와 매핑할 초기안이다.

| 보드 열 | 의미 | 카드에서 확인할 내용 |
|---|---|---|
| 등록·설정 | 종목을 등록했으나 감시 시작 전 | 코드·이름, 메모, 패턴 설정 여부 |
| 매수 감시 | 매수 조건을 감시 중 | 적용 매수 패턴, 현재 조건값·기준값, 최근 시세 |
| 매수 주문 중 | 매수 주문 후 처리 중 | 접수·체결·잔여 수량, 주문 가격, 경과 시간 |
| 보유·매도 감시 | 보유 수량에 매도 조건 적용 | 평균 매수가, 현재가, 보유량, 적용 매도·손절 조건 |
| 매도 주문 중 | 손절 또는 일반 매도 진행 중 | 매도 사유, 접수·체결·잔여 수량, 재처리 상태 |
| 종료 | 잔여 보유·주문이 정리된 거래 | 진입·청산 이력, 적용 패턴, 종료 사유 |

부분 매수 체결 시 ‘매수 주문 중’에도 보유 수량이 생긴다. 해당 카드에 보유량과 손절 감시 상태를 즉시 표시하고, 보드 열이 보유 단계로 바뀔 때까지 보호를 미루지 않는다. 부분 매도 후 잔여 수량도 계속 감시한다.

오류·연결 끊김·동기화 지연은 어느 열에서도 보이는 배지와 별도 필터로 제공한다. 종목 카드에는 매수 패턴과 매도 패턴을 별도로 표시한다. 시세가 없으면 가격을 임의 생성하지 않고 ‘미수신’으로 표시한다.

카드의 수동 이동으로 매수·매도·체결 상태를 바꾸지 않는다. 정렬과 그룹 변경은 화면 관리이고, 감시 시작·중지와 주문 상태 변경은 별도 동작이다. 모바일에서는 상태 탭과 카드 목록으로 같은 내용을 확인한다.

## 5. 종목 관리

사용자는 외부 사이트에서 찾은 종목코드를 직접 입력하거나 붙여넣는다. 종목명 검색은 입력 편의를 위한 마스터 조회이며 추천 기능으로 사용하지 않는다. CSV/JSON 일괄 등록은 확장 기능으로 두고 단건 입력을 먼저 완성한다.

종목별로 다음 정보를 관리한다.

- 종목코드·종목명·시장, 추가 출처·참고 링크·메모.
- 적용 매수 패턴과 매도 패턴, 종목별 조건값.
- 매수 금액 또는 수량, 주문 방식, 감시 시작·종료 조건.
- 실제 엔진에 적용된 설정 버전과 반영 시각.
- 보유량·미체결 주문 및 현재 감시 상태.

단순 등록만으로 주문을 시작하지 않는다. 사용자가 패턴과 주문 설정을 지정해 감시를 시작하면 엔진이 설정을 수락한 뒤 조건을 감시한다. 이는 전략 평가나 후보 승인 절차가 아니다.

초기에는 같은 계좌·종목에 하나의 활성 실행 설정을 두어 여러 패턴의 중복 주문을 피하는 안을 기본으로 한다. 여러 매수 패턴의 동시 실행은 별도 필요가 확인되면 확장한다.

보유·미체결이 있는 종목은 목록 삭제로 감시가 사라지지 않도록 보관 처리한다. ‘신규 매수 감시 중지’와 ‘보유 포지션의 매도 보호’ 상태를 구분한다. 신규 매수 중지가 손절 감시 중지를 의미해서는 안 된다.

## 6. 매수·매도 패턴 관리

패턴은 이름만 붙인 전략 태그가 아니라, 엔진이 실행할 수 있는 명시적인 조건과 행동의 묶음이다. 구체 패턴 종류와 수치는 이후 사용자와 정의한다. 본 문서에서 특정 가격·손절률·수익성을 확정하지 않는다.

| 패턴 구성 | 정의할 내용 |
|---|---|
| 기본 정보 | 패턴 ID, 이름, 설명, 매수/매도 구분, 활성 상태, 버전 |
| 매도 목적 | 손절 또는 일반 매도. 추가 유형은 추후 확정 |
| 관측 대상 | 현재가·체결가·봉 가격·수량 등 사용 데이터와 기준 시각 |
| 기준 시간 | 틱 즉시 판단인지, 지정 시간봉의 확정 후 판단인지 |
| 조건 | 기준값, 비교 연산, AND/OR 조합, 조건 유지·재발동 규칙 |
| 주문 행동 | 매수/매도, 수량·비율, 주문 방식, 적용 가능한 거래 시간 |
| 우선순위 | 여러 조건 동시 충족 시 처리 순서. 보호 손절을 우선하는 기본안 |
| 주문 후 처리 | 미체결·부분체결·거절·취소 확인, 재주문 조건과 한도 |

‘칼손절’용 조건은 즉시 판단할 수 있는 데이터와 규칙으로 명확히 정의한다. 봉 마감 확인형 조건을 사용하는 경우 해당 시각까지 기다린다는 점을 UI에서 구분한다.

패턴 수정은 새 버전으로 기록한다. 사용 중인 종목과 보유 포지션에 어떤 버전을 적용할지 명시하고, 엔진 수락 전에는 ‘반영 대기’로 표시한다. 사용 중인 패턴을 삭제해 보유 포지션의 청산 규칙이 사라지지 않도록 비활성화·이력 보존을 기본으로 한다.

## 7. 매매 실행과 손절 감시

기본 실행 순서는 종목 등록 → 매수·매도 패턴 연결 → 감시 시작 → 매수 조건 감지 → 주문·체결 추적 → 체결 수량에 대한 매도 감시 → 매도 조건 감지 → 청산 주문·체결 추적이다.

손절 신호가 발생하면 설정된 규칙에 따라 추가 사용자 확인 없이 청산 주문을 실행한다. 화면은 조건 감지, 주문 요청, 증권사 접수, 부분체결, 완료를 구분해 보여준다. 조건 감지 시각·주문 요청 시각·체결 시각을 기록해 실행 지연을 확인한다.

손절 신호와 다른 주문이 겹칠 때는 현재 보유량·매수 잔여 주문·기존 매도 주문을 먼저 일치시킨다. 잔여 매수 취소 중 추가 체결되는 경우까지 반영하고, 취소 확인 없이 같은 수량의 매도 주문을 반복하지 않는다. 재시작 시에는 실제 주문·보유 상태를 확인한 뒤 감시를 복원한다.

조건 충족 후 신속히 주문하는 것이 구현 목표다. 특정 가격이나 시간 내 체결 보장을 의미하지 않는다. 시세·증권사 연결이 끊겼을 때는 감시가 정상인 것처럼 표시하지 않고 마지막 수신 상태와 실행 불가 사유를 드러낸다.

## 8. 배포·데이터 구성 방향

기존에 논의한 Vercel 웹 + 관리형 DB + Windows 실행 엔진의 배치 방향은 유지한다.

| 구성 | 책임 |
|---|---|
| Vercel 웹·API | 보드, 종목·패턴 관리, 로그인, 실행 설정 전달과 결과 조회 |
| 관리형 DB | 종목, 패턴 버전, 실행 설정, 상태·이벤트와 웹 조회용 주문·체결 데이터 |
| 로컬 엔진 | 시세 수신, 실제 패턴 판단, 주문·체결·손절 처리, 재시작 복구 |
| 동기화 경로 | 웹 설정의 엔진 전달, 수락·거절 응답, 실행 상태·이벤트 업로드 |

손절 판단과 청산은 엔진에서 수행하고 웹 페이지 열림 여부나 보드 새로고침에 의존하지 않도록 한다. 웹 연결이 끊겨도 로컬 엔진이 동작 중이며 시세·증권사 연결이 유지되면 이미 적용된 보호 규칙을 계속 수행하는 방향으로 구현한다. 엔진이 실행되는 PC가 꺼지면 해당 엔진의 감시·주문은 수행되지 않는다.

웹에 저장한 설정과 엔진에 적용된 설정을 구분한다. 중복 전달·오래된 설정 재전송을 처리하고, 엔진의 수락 응답 없이 ‘감시 중’으로 표시하지 않는다. 주문·체결의 실제 상태는 증권사 및 로컬 실행 기록과 대조한다.

실거래 자동매매 기능을 위한 구조 개편과 실제 계좌에서의 활성화는 구분한다. 현재 문서 저장은 기존 실거래 제한을 해제하거나 계좌 주문을 시작하는 지시가 아니다.

## 9. 개발 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 기존 소스 재분류·개편 범위 확정 | 전략 검증·선정 경로와 실행에 필요한 공통 기능을 식별하고 제거 대상 문서화 |
| 2 | 보드·종목 관리·패턴 관리 기본 화면 | 종목 등록, 패턴 작성·연결·저장, 상태별 카드 표시 가능 |
| 3 | 손절 감시·청산 엔진 | 체결된 수량부터 보호하며 부분체결·미체결·중복 신호·재시작 처리 확인 |
| 4 | 매수 패턴 실행 연결 | 설정 수락 후 조건 감지·매수 주문·체결부터 매도 감시까지 이어짐 |
| 5 | 실제 상태 동기화·Vercel 사용 | 로그인 후 PC·휴대폰에서 설정과 실제 엔진 상태를 구분해 확인 |

화면을 먼저 확인할 때 예시 데이터는 명확히 표시한다. 실제 동작 연결 후에는 조건 충족, 중복 이벤트, 연결 중단, 부분체결, 재접속 등 실행 시나리오를 테스트한다. 이 테스트를 전략 성과 평가나 후보 승인 단계로 바꾸지 않는다.

정확한 TASK 번호·파일 경로·재사용 가능 모듈은 최신 저장소 확인 후 확정한다. 실제 매수·매도 패턴의 종류, 조건식, 시간 단위, 주문 방식은 패턴 상세 명세에서 정한다.

## 10. 이후 작업 시 참조 지침

1. 본 문서를 프로젝트 개편의 우선 기준으로 읽는다.
2. 전략 검증 대시보드·후보 점수·성과 검증·검증 기반 감시 승인 흐름을 새 작업에 다시 포함하지 않는다.
3. 종목 입력, 매수·매도 패턴 관리, 보드 상태, 주문 실행과 손절 감시를 중심으로 TASK를 작성한다.
4. 전략 검증 제거와 실행 조건 감시·주문 오류 방지를 혼동하지 않는다.
5. 변경 후 결과 문서에는 실제 구현·확인한 내용과 아직 연결되지 않은 내용을 구분해 남긴다.
