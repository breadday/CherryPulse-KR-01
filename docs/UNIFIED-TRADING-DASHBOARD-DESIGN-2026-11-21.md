# CherryPlus 통합 자동매매 대시보드 — 화면 우선 설계안 (2026-11-21)

상태: **사용자 검토용 초안 / 실제 주문 연결 금지**  
원칙: 기능을 추가하기 전에 사용 화면을 먼저 완성하고 검토한다.

## 1. 제품 목표
CherryPlus는 여러 증권사의 **국내·해외 주식 계좌, 보유종목, 주문, 예약, 자동매매, 운영상태를 통합 관리**하는 플랫폼이다.
종목헌터(후보 선정), 키움트레이더(우선 검증하는 키움 주문 실행기)와 역할이 겹치더라도 기능을 중복 개발하지 않고 검증된 계약/모듈의 재사용 여부를 검토한다.

## 2. 기존 상태와 보존 원칙
- 현재 `web/board/index.html`은 브라우저 초안 종목·매수/손절 패턴과 서버 초안 저장 중심이며, 감시·주문은 비활성 상태다.
- 기존 화면·설정·원장·문서·배포는 이번 설계 단계에서 **변경/삭제하지 않는다**.
- 새 UI는 별도 경로의 시안으로 개발하고 기존 화면으로 되돌아갈 수 있게 한다.
- 화면 개발 전 기존 문서와 UI 파일은 기준 커밋 SHA 및 파일 목록을 기록하고, 실제 수정 시 `back/ui-before-unified-dashboard/` 같은 별도 보존 폴더 또는 Git 태그/브랜치로 추적한다. 비밀정보·개인 계좌 데이터는 복제/커밋하지 않는다.
- 이 문서는 구동 테스트/주문 검증이 아니라 설계 초안이다.

## 3. 정보 구조
1. **통합 홈**: 전체 자산(원화 환산 기준·환율/조회시각 표기), 국내/해외 평가손익, 연결 증권사 수, 자동매매 가동/중지, 마지막 동기화와 오류.
2. **계좌·보유종목**: 증권사→계좌→시장(KR/US) 필터, 종목·통화·수량·평균단가·현재가·평가손익·조회시각. 데이터 미수신은 0원이 아니라 '미조회'.
3. **주문·예약**: 증권사/계좌 선택→종목 검색→매수·매도→시장가/지정가→수량/가격→예상 주문금액/가능수량 확인→최종 확인. 예약은 증권사 기본 예약과 PC 조건감시 예약을 분명히 구분.
4. **주문·체결 내역**: 접수/부분체결/체결/거절/취소/미확인(UNKNOWN), 증권사 주문번호, 원주문번호, 체결수량, 잔량, 최근 확인시각.
5. **자동매매**: 전략별 ON/OFF, 감시 대상, 장별 동작 시간, 주문 상한, 일일 손실 제한, 기본 일봉 손절 5%, 실패 시 신규 주문 중지. 초기 모두 OFF.
6. **운영·알림**: API 인증/연결, PC 실행기, 마지막 동기화, 예약 작업, 장애 복구 및 알림 기록.
7. **설정**: 증권사 연결상태(비밀값 비표시), 통화/환율 출처, 계좌별 권한, 시장별 일정, 데이터 보존.

## 4. 데스크톱 첫 화면 와이어프레임
```text
┌ CherryPlus ── [모의/실전 표시] [주문 OFF] [마지막 동기화] ──┐
│ 통합 홈 │ 계좌 │ 주문·예약 │ 체결 │ 자동매매 │ 운영 │ 설정 │
├─────────────────────────────────────────────────────────┤
│ 총자산       오늘 손익       주문 대기       실행 상태        │
├──────────────────────────────────────┬──────────────────┤
│ 증권사/계좌/국가 필터                │ 신규 주문         │
│ 보유종목 테이블                      │ 예약 목록         │
│ 종목 / 수량 / 평가액 / 손익 / 갱신시각 │ 미확인 주문 경고   │
├──────────────────────────────────────┴──────────────────┤
│ 체결·오류 타임라인 / 미확인 상태 / 운영 로그               │
└─────────────────────────────────────────────────────────┘
```
모바일에서는 핵심 상태·보유·주문·체결을 아래 탭으로 전환하되, PC용 필수 필드가 임의로 사라지지 않도록 상세 패널 제공.

## 5. 실제 동작 시나리오(최우선)
직장인이 퇴근 후: 계좌 선택 → 종목 직접 검색 → 주문 수량·지정가 입력 → **다음 거래일 예약** → 예약 등록 상태 확인 → 다음 날 모의 실행 → 저녁에 접수/부분체결/체결/미체결 결과 확인.
완료 판정은 각 단계에서 **UI 상태·백엔드 기록·증권사 응답**이 같은 주문 ID로 연결되는 경우뿐이다.

## 6. 개발 순서와 완료 조건
- UI-01: 예시 데이터로 작동하는 새 **통합 홈·계좌·주문·예약·체결** 클릭형 화면. 버튼 무반응/잘림/모바일 깨짐 없음. 주문 전송 없음.
- UI-02: 화면 리뷰 후 레이아웃 확정. 화면 명세(필드, 빈 화면, 로딩, 오류, 권한)를 고정하며 임의 메뉴 추가 금지.
- DATA-01: 키움 **모의** 계좌 1개 조회로 계좌/보유/주문 읽기 경로 연결. 오류·오래된 조회 명시.
- ORDER-01: 한 종목 수동 모의 주문의 사전 확인→접수→체결/미체결/취소 연동을 사용자 PC에서 검증.
- SCHEDULE-01: Windows 예약 및 체결 결과 복구; 재실행 중복 차단, UNKNOWN에서 자동 재전송 금지.
- EXPAND-01: 증권사별 API 지원범위·해외시장 통화/거래시간/주문유형 확인 후 다른 증권사를 **하나씩** 연결.
- STRATEGY-01: 위 실행 경로가 안정화된 뒤 전략 자동 판단과 종목헌터 연동.
- 백테스트/데이터 대량 수집/전략 최적화는 이번 단계의 선행조건이 아니다. 다만 주문 안정성 및 오류 복구에 필요한 테스트는 생략하지 않는다.

## 7. 필수 안전 규칙
- 화면의 '예약' 클릭과 증권사 접수는 별개 상태로 표시. PC 실행 기반 예약의 경우 PC 오프라인 상태 경고.
- 실전 주문은 초기 비활성; 사용자 명시 승인, 계좌 식별, 투자금/손실 한도, 모의 주문·체결 검증 이후 별도 활성화.
- 주문 요청 식별자와 영속 원장으로 중복 방지; 미확인 주문을 임의 재전송하지 않음.
- 실제 데이터가 없으면 예시임을 크게 표시. 화면 시안의 금액·수익률은 임의 실제값으로 보이지 않게 함.
