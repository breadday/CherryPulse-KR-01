CHANGES_REQUESTED

Evidence:

- The required restart and late-session test files are absent. The reported suite contains only 8 tests, so the specification's restart matrix (missing/ambiguous IDs, pending-query failure, zero position, CANCEL_REQUESTED) and 14:40/15:20/15:35 boundary behavior are not proven.
- `engine.py:_reconcile_risk_event` changes a `CANCEL_REQUESTED` event to `RETRY_PENDING` as soon as the order disappears from pending, even when `cancel_requested_at` is still within the confirmation timeout. The specification explicitly forbids reordering during that window.
- `core/models.py` and `core/order_manager.py` were not updated as required. Risk metadata remains dynamically attached and there is no risk-specific OrderManager lookup/helper or documented conservative remaining-quantity helper.
- More seriously, `broker/kiwoom_broker.py:place_order` returns an `Order` containing only the local `ORD_...` ID; it does not preserve a broker order number. `_submit_risk_sell` consequently stores that local ID as `broker_order_id` until a fill arrives. A restart with an unfilled live risk order cannot reliably match the broker pending order, violating the local/broker identity and restart-recovery requirements.
- In `on_heartbeat`, `auto_shutdown()` runs before risk observation. At the shutdown boundary, `shutdown()` puts observation, pending sync, and account sync in one try block, so a pending-sync exception prevents the account-sync attempt. These calls also have no explicit bounded timeout in this change, and `os._exit(0)` follows immediately; the required final reconciliation is therefore not demonstrated as bounded and independently attempted.
- The change does place `_check_risk_guard` before news, daily-cache, strategy, and ordinary sell gates on valid ticks, and it avoids creating a stop from stale heartbeat data. The fake-broker tests also cover rejection, cancel request/pending persistence, cancel-confirm timeout, and one partial pending restore case. However, those limited tests do not establish the full fail-closed, duplicate-fill, retry-limit, exception, storage-failure, or late-session acceptance cases.
- Verification observed: `python -m pytest -q` produced `8 passed`; compile checks were reported as successful; `git diff --check` had no whitespace errors (with only LF/CRLF warnings). These results do not close the missing acceptance coverage or the identity/retry defects above.

Required before approval: add and run the specified restart/late-session tests, preserve and reconcile distinct local and broker IDs, keep `CANCEL_REQUESTED` non-retryable until the defined confirmation rule is satisfied, and make shutdown reconciliation independently bounded/fail-closed with tests for the required failure paths.
