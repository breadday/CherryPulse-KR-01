# REBUILD-04 미전송 의도 폐기

2026-09-15. [명령 만료·버전 검증](REBUILD-04-COMMAND-FRESHNESS.md)의 후속 작업이다.

## 사용 계약

`Ledger.discard(request_id, reason=..., expected_revision=...)`는 현재 원장을 검토한 뒤 미호출 의도를 명시적으로 종료하는 로컬 가상 API다. 새 폐기는 True, 동일 요청·동일 사유의 재조회는 False를 반환한다. 원문 요청은 삭제하지 않는다.

- 계좌 소유·시작 게이트와 최신 원장 revision을 확인한다. 오래된 검토는 STALE_DISCARD_REVIEW로 거절한다.
- INTENT_PERSISTED이며 접수·체결 증거가 없는 요청만 허용한다. SENDING/SENT/UNKNOWN/RECONCILING은 폐기할 수 없다.
- 요청별 고정 이벤트 ID에 SEND_FAILED / NOT_INVOKED와 사유를 기록한다. 원장과 outbox가 같은 트랜잭션으로 반영된다. 기존 미전송 증거와 수량 계산을 재사용한다.
- 같은 요청·같은 사유의 재시도는 이후 revision이 바뀌어도 추가 기록을 만들지 않는다. 다른 사유로 덮어쓰려 하면 CONFLICT_EVENT_ID_MISMATCH다.
- 신규 매도 의도 폐기는 해당 예약을 해제하지만 관리량·체결량·취소량을 변경하지 않는다. 취소·정정 의도의 폐기는 원주문의 예약을 해제하지 않는다.
- 폐기한 요청을 같은 키로 제출해도 기존 결과만 반환하며 재전송할 수 없다. 다시 실행하려면 현재 조건으로 새 키의 의도를 작성해야 한다.

이 API는 증권사 취소 명령이 아니다. 만료나 버전 변경만으로 자동 호출하지 않는다. 사유는 현재 내부 ASCII 코드이며 사용자 설명·인증 주체·외부 명령 권한 계약은 후속 구현이다. 실제 어댑터에서 미호출 증명의 신뢰 경계를 별도로 검증해야 한다. 폐기 이후 모순된 실제 체결 증거는 기존 원장 정책에 따라 보존·대조한다.

## 검증 결과

- 신규 6개 검사 포함 전체 **78개 통과, 7.06초**.
- 미전송 신규 매도의 예약 해제, 중복 폐기, 사유 충돌, 오래된 검토, 이미 전송된 요청·체결 증거가 있는 요청의 거절, 미전송 취소 폐기 시 원주문 예약 유지를 검사했다.
- Ruff ALL·basedpyright 오류/경고 0. Python 코드 규칙 28개 파일 위반 0.
- 별도 임시 DB를 직접 실행해 예약 100 → 폐기 후 DB 재로드 예약 0, 중복 폐기 False, 취소량 0, 전송 False·가상 호출 0을 관측했다.

실제 주문·배포·운영 DB 변경은 수행하지 않았다. 다음 작업은 대조 불일치의 해소 근거와 원문 격리, 외부 명령 인증·권한, 실제 패턴 설정 계약이다.

가상 수량 불일치의 개별 대조 해소와 불일치 전용 종목의 시작 차단은 [후속 구현 기록](REBUILD-04-RECONCILIATION.md)을 따른다. 최신 전체 검사는 86개 통과이며 실제 조회 근거 검증은 미완료다.
