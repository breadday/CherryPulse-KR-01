## 개발 시 지켜야 할 구조

- `Scope`는 virtual 어댑터·계좌 내부 ID·환경·execution UUID를 포함한다. 같은 DB에서도 범위별 요청 키·배정·이벤트를 분리한다. 종목은 요청 내용에 포함하므로 같은 범위/키의 다른 종목도 충돌이다.
- 요청 JSON의 십진 가격을 정규화한 후 원문 의미와 SHA-256을 기록한다. 동일 키 비교는 현재 잔량 검사보다 먼저 수행한다. 요청 종류가 달라도 같은 키를 재사용하면 충돌한다.
- `BEGIN IMMEDIATE`에서 중복 확인·업무 검사·요청/사실 기록을 직렬화한다. journal 고유 제약과 outbox 삽입 트리거가 같은 트랜잭션에 속한다. 트리거 실패 시 체결 사실도 남지 않는다.
- 포지션·예약·보호·청산 수량은 별도 가변 캐시 없이 고유 journal 사실에서 계산한다. 따라서 한 체결의 일부 효과만 커밋되는 경로가 없다. 재시작 후 같은 기록으로 복원한다. 현재는 전체 scope를 읽는 소규모 검증용 구현이다. 운영 데이터 규모의 성능·보관/압축 정책은 미검증이다.
- 예약은 신규 매도 요청 기록부터 생기며 제출로 관리량을 줄이지 않는다. 취소 요청/접수만으로 해제하지 않는다. 확인된 취소·감액·체결만 노출을 줄인다. 증액 정정은 감사 기록을 남기고 전송하지 않는다.
- `Q0 + D - F - C - A`의 차이를 보존한다. 종료 후 지연 체결도 반영하며, 취소량을 조용히 수정하지 않는다. 더 최신 증거가 취소 완료와 모순되면 합계가 맞아도 대조 대상으로 남긴다.
- `evidence_version`은 **가상 시나리오가 제공하는 인과 순서**다. 키움이 이 필드를 제공하거나 실제 콜백이 정렬된다는 가정이 아니다. 실제 어댑터는 고유 체결 식별·연결·잔량 시점의 증거를 확인하기 전 활성화하지 않는다.
- dispatcher는 호출 전에 SENDING을 커밋한다. 같은 요청은 두 dispatcher가 경쟁해도 한 번만 가상 전송한다. SENDING/SENT/UNKNOWN과 효과 미확정 ACKED는 재시작 대조 대상이며 자동 재전송하지 않는다.
- 부분 매수로 증가한 관리량은 즉시 보호 대상 수량이다. 가상 청산 모드에서는 남은 청산 의무를 기록하고 확인된 매도 여력만 제출한다. 매도 UNKNOWN이나 수량 불일치가 있으면 추가 매도를 차단한다.
- 저장된 `Control`은 가상 실행 스위치다. 웹 명령의 인증·권한·만료·기대 버전이나 실제 손절 조건 판단을 구현한 것은 아니다. `protected`는 보호 의무 수량이며 실제 손절 주문이 실행됐다는 표시가 아니다.

매트릭스 검사는 내부 수량·예약·멱등성 동작을 확인한다. T08은 취소/체결 도착 순서 양쪽을 실행한다. 각 시나리오에서 저장된 요청·이벤트를 재생하여 추가 변경과 추가 가상 전송이 없음을 검사한다. T06은 불일치 증거를 반복해도 보유를 자동 보정하지 않는 범위이며, 운영 스케줄러의 24시간 경과 검사는 아니다.

Ruff ALL 및 포맷 검사, basedpyright all 검사, Python 코드 규칙 검사도 실행한다. 재현 명령과 도구 설치는 [개발 환경](DEVELOPMENT-ENVIRONMENT.md)을 따른다.

직접 실행한 가상 데모의 관측값:

```json
{"managed":70,"reserved":0,"cancel_unknown_reserved":100,"cancel_confirmed_reserved":30,"lifecycle":"CANCELLED","virtual_calls":2,"replay_changes":0}
```

의미: 관리100주에서 매도 요청 → 취소 UNKNOWN(예약100 유지) → 실제 취소70 확인(예약30 유지) → 지연 체결30(관리70·예약0) → 재시작 재생(변화0). 외부 시세·로그인·주문 호출은 없다.

## 남은 작업과 다음 순서

1. 실제 어댑터 전에 요청 거절/명확한 미전송 실패·effect 거절, 원문 격리, 주문번호 연결 이력, 대조 해소 근거를 추가한다. 현재 미확인 증거는 자동 해소하지 않는다.
2. 단일 PC 계좌/환경 OS 잠금, 명령 권한·버전·만료, 재시작 후 전송 재개 조건을 완성한다. 현재 SQLite 동시 쓰기 검증은 계좌 OS 잠금 검증을 대신하지 않는다.
3. 매수/손절 패턴의 실제 조건과 설정 버전 적용, 청산 완료/재개 이력, 외부 보유 인계를 구현한다. 가상 청산에서 사용하는 시장가·정규장·DAY·설정버전1은 데모 조건이며 실주문 기본값이 아니다.
4. API 미확인 사항을 해소하고 허가된 계좌 연동 검증을 별도 수행한다. 이후 보드와 동기화를 연결한다.

기존 back/ 보관본을 import하지 않았다. .env·운영 DB·실제 계좌 데이터는 읽거나 변경하지 않았고, 커밋·push·배포도 실행하지 않았다.
