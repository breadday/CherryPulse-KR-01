## 확정된 D03 정책 — 2026-10-12

- 손절 시장가가 30초 안에 미체결이면 운영자 경고와 수동 검토 상태로 전환한다. 자동 재주문은 금지한다. 전송 결과가 `UNKNOWN`이면 주문·체결·잔고 대조 전 재주문하지 않는다.
- 즉시 알림 조건: 손절 보호 실행 불가/미완료, 시세 중단 1분 이상, 시세 노후 30초 이상, 세션 밖 보호 대상 존재, 미해결 주문 5분 이상, 원장·잔고 불일치 감지.
- 상태 변경 시 즉시 알림. 같은 상태는 10분 간격 최대 3회 후 30분 간격으로 완화한다. 운영자 확인 시 중지한다.
- 외부 알림 채널은 Telegram으로 선택했다. 송신 어댑터는 준비됐지만 봇 토큰/개인 채팅 ID를 로컬에 설정하고 알림 호출자·실패 기록을 연결하기 전 외부 전송은 하지 않는다.
- 기존 보유 자동 편입 금지. 사용자가 종목별 수량·원가·손절 규칙 버전을 명시 배정한 뒤 보호 편입한다. 불명확한 주문/잔고는 격리 표시하고 수동 확인 전 주문을 차단한다.

## 확정된 D08 정책 — 2026-10-12

- **폴링:** 정상 5초, 타임아웃 3초. 네트워크 오류·5xx·타임아웃만 재시도하며 5초부터 지수 백오프, 최대 대기 5분. 성공 뒤 정상 주기로 복귀. 4xx는 재시도하지 않고 운영자 확인 상태.
- **명령 충돌:** 계좌·환경 범위의 서버 발급 단조 증가 순번과 `expected_version`이 모두 맞을 때만 적용. 충돌·역순·오래된 버전 자동 병합 금지. 거절 후 보드에서 최신 설정을 다시 불러와 제출. 오프라인 명령은 서버 수신 시각 기준 순번을 새로 받고, 더 높은 순번이 적용된 뒤 도착하면 거절.
- **인증/권한:** 사용자 본인만 접근, 지정 운영자 없음. 사용자가 웹 관리 화면에서 계좌·환경 권한을 부여/회수. Supabase Auth의 `auth.uid() = owner` 및 명시적 계좌·환경 연결을 모두 만족할 때만 읽기/쓰기, 나머지는 기본 거부. 권한·명령·설정 변경 감사 이력 1년 보존(법규 필요 시 연장).
- **outbox:** 계좌·환경별 서버 발급 단조 증가 정수 순번. HTTP 200과 해당 순번 반영 확인 전 로컬 outbox 삭제 금지. ACK 후 로컬 원장에 7일 유지한 뒤 압축 보관 30일. 삭제는 별도 운영 보존 정책에서만 수행. 재전송 중복 방지 키는 순번.
- **장기 단절:** 마지막 성공 동기화 후 5분에 보드 경고, 30분에 Telegram 운영자 알림 기준. 엔진 PC 실행을 확인할 수 없으면 `엔진 오프라인 - 마지막 동기화 n분 전`으로 표시. 폴링 성공 전 하향 명령은 실행하지 않는다. 알림 실패는 로컬 상태에 기록한다. 개인 채팅 연결은 구현 대기.

## 확정된 D05 일반 매도 정책 — 사용자 결정

- 목표수익 +5%, +10%는 알림만 발생시킨다. 일반 매도 제출은 사용자가 직접 한다. 당일 15:10 시간 알림은 1회다. 자동 매도 트리거는 없다.
- 매도 수량 기본값은 전량이다. 부분 매도는 50% 단위로 허용하고, 체결 후 남은 수량에는 기존 손절 규칙을 유지한다.
- 지정가가 기본이며 현재가를 가격으로 사용한다. 시장가는 확인 팝업을 거친 명시 제출만 허용한다. 주문 유효기간은 당일이고 IOC/FOK는 사용하지 않는다.
- 60초 미체결 시 취소 후 수동 검토로 전환한다. 자동 재주문하지 않는다.
- 손절과 일반 매도가 동시에 가능하면 손절이 우선한다.
- 50% 계산 결과가 홀수 수량에서 정수가 되지 않을 때의 반올림/거절 규칙과 목표수익 알림 재발송 억제 단위는 미확정이다. 관련 규칙이 정해질 때까지 부분 수량은 정수 수량을 명시한 경우에만 허용하고, 알림의 영속 중복 억제/주문 연결은 비활성으로 둔다.

## 알림 채널 선택

D03/D08 운영 알림 채널은 Telegram으로 선택했다. 봇 채팅에서 `/start`를 보내는 것만으로 앱 전송은 시작되지 않는다. `notifications/telegram.py`에는 토큰/채팅 ID를 환경변수에서 읽는 송신 어댑터가 있으나 알림 호출자와 로컬 실패 기록은 미연결이다. 토큰은 저장소·문서·채팅에 넣지 않는다.

## 다음 순서

1. 확정 D05 정책을 계약 문서에 반영하고, 50% 정수 산정과 알림 중복 억제 상태의 남은 경계를 명시한다. 사용자 명시 동작 없는 매도 주문은 생성하지 않는다.
2. D08 로컬 가상 동기화/복구와 실패 상태/outbox를 구현한다. 실제 Supabase 프로젝트·인증 비밀값·운영 DB는 사용하지 않는다.
3. Q01~Q11 키움 근거와 D02 실기기 확인을 별도 증거 작업으로 진행한다.

정책 계약·가상 검사와 실제 키움 검증, 운영 DB 변경, 배포는 별도 구분한다. 실제/모의 주문 API 호출·운영 DB 변경·배포는 별도 명시 요청 없이 수행하지 않는다.
