# CherryPulse-KR-01 진행 현황 및 미개발 사항

- 확인 기준일: 2026-10-18 (KST)
- 기준 저장소: `main` / `d5e5fae` (`origin/main`과 일치)
- 기준 개발 방향: [개발방향](CherryPulse-KR-01-Development-Direction.md)
- REST 진행 기준: [REST 전환 계획](treadding/REST-MIGRATION-PLAN.md), [상태 JSON](treadding/REST-MIGRATION-STATUS.json), [인계 문서](treadding/REST-MIGRATION-HANDOFF.md)
- 범위: 문서와 현재 소스의 정적 비교. 이 문서를 만들면서 주문/API/운영 DB/배포나 기능 테스트는 실행하지 않았다.

## 1. 요약

프로젝트는 **로컬 브라우저 초안 보드와 증권사 독립형 가상 원장, REST/WebSocket 오프라인 경계**까지 구현되어 있다. 매매 수량·중복·부분체결·취소 경합·재시작 등 안전 계약의 상당 부분은 코드와 가상 검사로 다룬다.

반면 실제 REST 주문 dispatcher, 브로커 주문·체결을 로컬 원장에 반영하는 연결, 지속적인 시세 감시와 손절 실행, 웹/엔진 동기화는 아직 연결되지 않았다. 상태 JSON도 `orders_enabled: false`, 현재 작업 `R04`로 기록한다. 따라서 현 상태를 실제 자동매매가 가능한 시스템이나 end-to-end 검증 완료로 표현할 수 없다.

## 3. 미개발·미검증 항목

### P0 — 실제 계좌/주문 경계를 열기 전 필요한 근거

1. **R04 식별·수량 의미 실증**
   - 모의 조회 5종은 완전 조회였지만 빈 결과였다. 주문번호 유일성(Q01), 체결 고유키/수량 의미(Q02), 접수 전 체결 상관관계(Q08)는 미확정이다.
   - 정정·취소 효과(Q03/Q04), 전송 결과와 안전한 재시도 구분(Q05), 매도 가능 수량과 예약 반영(Q06), 조회 이력 보존/페이지 완전성(Q07)도 충분한 증거가 없다.
   - 다음 게이트는 계획 문서에 적힌 모의 1주 지정가 제출·주문/체결 이력 대조다. 이는 실제 주문 API 호출이므로 이 보고서는 실행하지 않았다. 사용자가 정한 PC·모의 환경에서 승인된 절차로 별도 실행해야 한다.

2. **REST scope와 원장 연결**
   - 현재 `execution.models.Scope`는 virtual 범위에 한정된다. `adapters/kiwoom_rest_scope.py`의 제안은 증거 게이트와 운용자 승인 없이는 실행 scope를 만들지 않는다.
   - 실제 계좌/앱 범위 확인, 주문·체결 식별, 조회 결과의 신뢰도 및 외부 보유 구분을 해소하기 전 `can_reconcile`이나 주문 허용을 켜면 안 된다.

### P1 — 실시간 매매 기능의 주요 미개발 영역

3. **R05 실제 주문 dispatcher**
   - REST 신규/정정/취소 요청을 단일 dispatcher로 보내고, 전송 전 내구성 기록·UNKNOWN 격리·ACK와 효과 확인 분리·부분체결/취소 경합·속도 제한·재시작 대조를 구현해야 한다.
   - 현재 도구는 제한된 모의 제출 실증용이며 실제 엔진의 `New/Amend/Cancel` 경로가 아니다. 자동 재전송/자동 취소/보호 주문 연결도 없다.

4. **R06 패턴 실행과 보호 연결**
   - 매수 평가 결과를 수락된 불변 설정에서 자동 감시하고, 체결된 수량부터 해당 버전의 손절 보호에 연결하는 end-to-end 경로가 없다.
   - 손절 청산 주문, 매수 잔량 취소 중 지연 체결, 매도 예약과 잔여 청산 의무를 브로커 증거와 연결해야 한다.
   - 일반 매도는 평가 계약 일부만 있다. 목표 알림의 영속 중복 방지, 15:10 타이머, 60초 미체결 취소 후 수동 검토, UI 제출 연결은 미완료다. 홀수 보유량의 50% 정수 처리와 알림 억제 단위도 결정이 필요하다.

5. **장중 시세·세션 증거**
   - WebSocket 실데이터 프레임 수신, 연결이 끊긴 동안 시세 신선도 무효화, 실제 거래일/세션 판정, 복구 후 재구독과 대조가 미완료다.
   - 로컬 테스트용 시각·세션 값을 실제 시장 근거로 승격해서는 안 된다. 연결 단절 때 정상 감시처럼 보이지 않도록 운영 상태 표시가 필요하다.

### P1/P2 — 운영·웹 제품 완성도

6. **R07 무인 엔진 운영**
   - 지정 Windows PC에서 장 시작/마감, 재시작, 네트워크·토큰 만료, 장시간 중단, 단일 계좌 프로세스 잠금, 상태 heartbeat를 실제 운영 절차로 검증해야 한다.
   - Telegram 어댑터와 폴링 재시도 정책 함수는 있지만 호출자, 실패 outbox, 실제 Supabase/Telegram 연결은 없다. 예약 작업 등록만으로 브라우저와 독립된 엔진 운영이 검증되지는 않는다.

7. **D08 클라우드 동기화**
   - Supabase Auth·계정/환경 권한, schema/RLS, desired→accepted→applied 전이, 단조 순번·expected version, 로컬 outbox 및 복구가 실제 서버와 연결되지 않았다.
   - 현재 D08은 정책 계약 및 일부 순수 정책 모듈 수준이다. 보드의 브라우저 저장과 REST 증권사 API는 이 동기화를 대신하지 않는다.

8. **R08 실제 상태 보드·D09/D10 인수**
   - 10월 18일 추가된 메인 보드 진입점/집계와 이번 합본의 로그 요약·매수 미리보기는 초안 기능이다. 실제 주문·체결·시세·설정 적용 상태 표시가 아니다.
   - 데스크톱/물리 모바일 기기 체크리스트 6/6, 엔진 수락 상태 표시, 장애 배지, 운영 계좌 인계, Vercel 배포 URL 검증은 미완료다.
   - 로그 파일 선택 화면은 파일 요약 UI이지 자동 로그 수집이나 브로커 상태 연결이 아니다.

9. **REBUILD-01/Q13 운영 환경 조사 마무리**
   - 문서상 특정 시점의 프로세스·예약 작업 검색은 부분 조사다. 모든 서비스/작업 스케줄러/외부 래퍼, 다른 PC, 현재 운영 DB의 계좌 관리 배정은 확인되지 않았다.
   - 실제 보유·미체결의 소유권과 인계 규칙을 확인하기 전 외부 보유를 자동 편입하거나 파일 이동을 인계 완료로 취급하지 않는다.

## 5. 문서 간 상태 차이와 갱신 필요

- [REST 상태 JSON](treadding/REST-MIGRATION-STATUS.json)은 10월 18일 기준 R04 진행, R08 보드 초안 집계, 주문 OFF로 기록한다. [REST 계획](treadding/REST-MIGRATION-PLAN.md)의 R08 “미완료”와 모순은 아니다. R08의 일부 화면 작업만 끝났고 실제 상태 보드/인수는 미완료다.
- `software_verification.board_node_tests: 24`는 메인 보드 요약 검증 기록이다. `d5e5fae`는 별도 로그 요약·매수 미리보기 모듈과 테스트 파일을 추가했다. 해당 테스트의 실행 결과가 아직 상태 JSON/검증 기록에 반영되지 않았다.
- [전면 개편 계획](CherryPulse-KR-01-Rebuild-Plan.md)은 9월 기준 상태가 많아 최신 REST 전환 진행을 전부 반영하지 못한다. 전체 계획의 현행 기준은 이 문서와 최신 REST 상태/인계/검증 기록을 함께 읽어야 한다.
- R05 상태 표기는 `DEMO_TOOL_OFFLINE_CI_ONLY`지만, [R05 실증 기록](treadding/REST-R05-ORDER-DEMO.md)은 10월 14일 사용자 PC에서 모의 주문 전송이 거절된 실증 1회를 기록한다. 도구가 한 번 호출된 사실과 주문/체결/원장 연결에 성공한 것은 다르므로, 다음 차수의 승인된 장중 재검증이 남아 있다.

## 6. 확인하지 않은 것

- 이번 점검에서는 소스/문서 비교와 저장소 상태만 확인했다. 계좌, 운영 DB, 예약 작업, 프로세스, 네트워크, Supabase, Telegram, 브라우저 렌더링, CI 최신 실행 및 실제 주문은 확인하지 않았다.
- 문서에 적힌 테스트 수와 외부 실행 결과는 그 문서의 기록을 인용한 것이며 이번 보고서 작성 중 재실행한 결과가 아니다.
- 작업 트리는 보고서 작성 전 `main`/`origin/main`이 `d5e5fae`로 일치하고 clean이었다. 이 보고서 파일은 새 로컬 변경으로 추가한다.
