# D02 관심종목·손절 패턴 보드 진행 기록

## 전체 보드 JSON 백업·복원 — 2026-09-25

관심종목 전용 JSON/CSV 가져오기·내보내기와 별도로 전체 보드 백업·복원을
추가했다. 파일은 `format: "cherrypulse-board-draft"`, `schemaVersion: 1`,
`symbols`, `patterns`를 가진다. 종목의 관심/보관 상태·이름·링크·메모·손절
연결과 모든 손절 패턴 버전·계열·활성 상태·기준값·주문 방식이 포함된다.
백업·복원은 브라우저 초안만 다루며 엔진 적용·감시·주문·클라우드 전송은 없다.

복원 파일은 10 MiB 제한, JSON/root/필드/schema 검증 후 종목코드와 중복,
패턴 ID·계열/버전 조합·역치·주문 방식, 종목→패턴 연결을 전부 검사한다.
잘못된 데이터가 하나라도 있으면 일부 적용하지 않는다. 전체 검증 후에는
대체될 종목/보관/패턴 수를 보여 주고 별도의 복원 확인을 거친다. 저장은
새 상태를 localStorage에 성공적으로 쓴 다음 화면 상태를 바꾸므로 저장 실패
시 현재 상태·화면을 유지한다. 내보내기도 같은 10 MiB 제한을 적용해 생성한
파일이 복원 크기 제한을 넘지 않게 한다.

구형 로컬 초안과 같은 선택 필드 누락은 복원 시 그대로 보존한다. 구형 패턴에
없는 버전·계열·활성·주문 방식을 추정해 파일에 채워 넣지 않는다. 현재 읽기
화면의 기존 호환 동작은 유지한다. 중복 코드/패턴 ID/계열 버전, 손상 JSON,
지원하지 않는 형식·버전, 잘못된 링크와 임계값은 복원 전에 거절한다.

변경 파일: `web/board/board-backup.js`, `board.js`, `index.html`, `styles.css`,
`board.test.js`; 기록 갱신: 이 문서, `WORK-CONTINUATION-STATUS.md`,
`DEVELOPMENT-GOAL.md`, `CherryPulse-KR-01-Rebuild-Plan.md`.

검증: Node 전체 테스트 **13 passed**. 전체 백업의 보관 종목·패턴 버전·활성 상태·
연결 왕복, legacy 필드 보존, 무효 입력·중복·고아 연결·미지원 버전 거절, 취소,
저장 실패 무변경과 reload 복구를 확인했다. Chrome headless 모바일에서는 백업
다운로드→확인 전 원본 유지→취소 후 원본 유지→복원 확정→reload 뒤 관계/상태 유지,
데스크톱에서는 검증·확인 화면·취소 동작을 확인했다. 물리 모바일은 미검증이다.

## JSON/CSV 종목 초안 가져오기 — 2026-09-25

관심 종목 패널에서 UTF-8 JSON 또는 CSV 파일을 브라우저 로컬 초안으로
가져온다. JSON은 `{code,name,source?,note?}` 객체 배열, CSV는 `code,name`
필수 헤더와 선택형 `source,note` 헤더를 받으며 열 순서, 따옴표·쉼표·줄바꿈을
지원한다. 허용 필드 외 값, 잘못된 종목코드·이름·링크·메모, 파일 내/기존
초안과의 중복 코드, 5 MiB 초과 파일은 거절한다. 모든 행을 먼저 검증하므로
하나라도 오류면 일부 종목을 추가하지 않는다. 가져온 종목은 패턴 미연결·미보관
상태이며 감시나 주문을 시작하지 않는다.

검증: Node 단위/DOM 모의 검사에서 CSV 따옴표·줄바꿈, JSON/CSV 정규화, 필드·행
오류, 중복 시 무변경을 확인했다. Chrome 모바일 emulation에서 가상 CSV 파일을
제출해 종목 2개가 모두 카드로 표시되고 저장 안내가 나오는 것까지 확인했다.
5 MiB 한도 초과 시 파일 읽기 전 거부하는 테스트도 통과했다. 실제 사용자 파일과
물리 모바일은 미검증이다.

## 관심종목 JSON/CSV 내보내기 — 2026-09-25

활성 관심종목이 있을 때 코드·이름·링크·메모를 가져오기와 호환되는 JSON 또는
UTF-8/BOM CSV로 다운로드한다. CSV는 `code,name,source,note` 헤더와 인용·이스케이프
규칙을 사용해 쉼표·따옴표·줄바꿈이 있는 셀도 가져오기와 왕복 호환된다. 보관
종목과 손절 패턴·종목별 패턴 연결은 내보내지 않으며, 따라서 전체 보드 백업이나
엔진 설정 내보내기가 아니다. 저장소 상태를 바꾸지 않고 다운로드는 사용자가
버튼을 눌렀을 때만 시작한다.

검증: Node 검사에서 두 형식 내용·필드 선택·보관 항목 제외·CSV 특수문자 왕복·Blob
URL 해제를 확인했다. Chrome 모바일 headless에서 두 버튼을 실제 클릭해 JSON/CSV
다운로드 완료 이벤트를 받았고, 내려받은 파일 내용을 읽어 활성 종목만 포함하는
것을 확인했다. 브라우저 에뮬레이션 외의 OS별 다운로드 동작은 미검증이다.

## 관심종목 검색 — 2026-09-25

현재 선택한 관심/보관 목록 안에서 종목코드·종목명·참고 링크·메모를 대소문자
구분 없이 검색한다. 검색은 초안 데이터를 수정·저장하지 않으며, 검색 결과가 없으면
빈 결과 안내를 표시한다. 결과 개수는 전체 관심/보관 수와 함께 보여 준다.

검증: Node DOM 테스트에서 네 검색 필드, 관심/보관 필터 조합, 빈 결과 표시를
확인했다. Chrome 모바일 emulation에서 HBM 메모 검색 후 보관 탭의 메모 검색을
실행했고, 390px 가로 폭 넘침 없음과 데스크톱 2열을 다시 확인했다.

## 불변 버전 초안 추가 — 2026-09-25

보드에서 저장한 손절 패턴을 기존 값에 덮어쓰지 않고 새 버전으로 만들 수
있도록 했다. 신규 패턴은 v1이며, 기존 패턴 카드의 `새 패턴 버전 만들기`는
이름·발동 기준·기준값·시장가/지정가 선택을 복사해 같은 패턴 계열의 다음
버전으로 저장한다. 주문 방식 선택은 로컬 초안일 뿐 실행 설정은 아니다.
지정가 가격, 호가, 거래 세션과 미체결 처리는 미정으로 남긴다.
이전 버전에 연결된 종목은 그대로 유지되고, 새 버전은 종목 카드에서 직접
다시 연결해야 한다. 버전 비활성화는 이후 새 연결만 막고 기존 연결과
초안 이력을 유지한다. 이미 연결된 비활성 버전은 종목 카드에 표시되며,
새 연결 대상으로는 선택할 수 없다. 재활성화하면 다시 선택할 수 있다.
구형 로컬 초안은 `version`이 없으면 v1, `patternId`가 없으면 기존 ID를
계열 ID로 취급하고 `active`가 없으면 활성 버전으로 읽는다.

검증: `node --test web/board/board.test.js` **13 passed**. 신규 버전 저장 뒤
기존 버전과 종목 연결이 보존되는 것, 비활성 버전의 새 연결 차단 및 재활성화를,
새 버전에 시장가/지정가 선택이 저장되는 것을 검사했다. `node --check
web/board/board.js`, `node --check web/board/board.test.js`, `git diff --check`
통과. Node 검사는 DOM 모의 환경이며 실제 Chrome 결과는 위의 JSON/CSV 진행 기록을
참조한다. 별도 회귀 확인으로
Python 3.10.8 32비트 전체 pytest **159 passed**, Ruff 검사·포맷 검사,
가상 데모, pip 의존성 검사가 통과했다. Python은 격리된 `.venv`가 아닌
사용자 설치 환경에서 실행했다. 로컬 초안의 버전 표시는 엔진의 불변 패턴
저장이나 적용 상태가 아니며 서버 저장·엔진 동기화는 미구현이다.

## 종목 기본 정보 편집

종목 카드에서 종목명·참고 링크·메모를 수정할 수 있게 했다. 종목코드는
이 보드의 등록 식별자로 유지하고 편집 폼에서는 바꾸지 않는다. 링크 입력은
저장 전 `http`/`https`를 확인하며, 저장된 텍스트는 DOM 텍스트 노드로
표시한다. 변경은 브라우저 초안에만 적용되고 엔진 설정은 바뀌지 않는다.
브라우저 저장 실패 시 성공 안내가 오류 안내를 덮지 않도록 했다.

검증: `node --check web/board/board.js` 통과. 브라우저 상호작용과 모바일
렌더링은 실제 브라우저 도구 부재로 확인하지 않았다.
