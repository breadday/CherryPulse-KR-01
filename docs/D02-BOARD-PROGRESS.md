# D02 관심종목·손절 패턴 보드 진행 기록

## 종목 초안 보관·복원

관심/보관 목록 필터와 카드별 보관·관심 복원 동작을 추가했다. 보관은
브라우저 초안의 표시 분류만 바꾸며 항목을 삭제하거나 엔진 설정·보유 보호를
변경하지 않는다. 이전 저장 형식에서 보관 필드가 없는 종목은 계속 관심
목록에 표시한다. 관심·보관 수를 함께 보여 준다.

검증: `node --check web/board/board.js` 통과. 실제 브라우저·모바일 동작은
브라우저 실행 도구가 없어 확인하지 않았다.

## 종목 등록 정보 보강

종목 등록 폼에 사용자가 직접 입력하는 종목명, 선택형 참고 링크와 메모를
추가했다. 카드에는 코드·이름·메모가 표시되고, 링크는 `http`/`https`만
클릭 가능하게 렌더링한다. 사용자 제공 문자열은 기존처럼 DOM
`textContent`로 출력하며 로컬 브라우저 초안으로만 보관한다. 종목 등록은
감시나 주문을 시작하지 않는다.

`node --check web/board/board.js` 통과. 실제 브라우저·모바일 렌더링은
브라우저 실행 도구가 없어 확인하지 않았다.

- 기준: GitHub `main`의 D01 계약과 `docs/NEXT-DEVELOPMENT-PLAN.md`
- 상태: **화면 골격 부분 구현**. 엔진 적용, 계정 저장, 실제 시세·주문은 연결하지 않았다.

## 구현

`web/board/`에 종목코드 6자리 수동 등록, 고정 가격/확인된 원가 대비 하락률
손절 패턴 초안 생성, 종목과 패턴 연결 화면을 만들었다. 브라우저 로컬 저장소에만
초안을 저장한다. 동일 종목 중복 등록, 잘못된 가격과 0 이상 1 미만 범위 밖의
하락률을 거절한다. 카드의 `미적용`, 상단의 `엔진 미연결`, 하단 설명은
등록만으로 감시나 주문이 시작되지 않음을 보여 준다. 사용자 입력은 DOM
`textContent`로 출력한다. 모바일 폭에서 두 칼럼을 한 칼럼으로 접는 CSS를
추가했다.

## 검증과 미완료

- `node --check web/board/board.js`: 통과.
- 브라우저 모바일 화면의 실제 상호작용·시각 확인: **미실행**. 이 환경에
  `agent-browser` 실행 파일과 Chromium 실행 파일이 없어 화면 검증을
  완료로 표시하지 않는다.
- 브라우저 로컬 저장은 계정 인증이나 Windows 엔진의 수락/적용 상태가
  아니다. 등록 데이터의 서버 저장, 편집·버전 충돌, 매수 패턴,
  외부 후보 JSON/CSV 입력, 적용 승인과 엔진 동기화는 미완료다.
- 실제/모의 키움 주문 API, 운영 DB, 배포를 호출하지 않았다.

다음 단계는 모바일 실제 화면 확인, D01의 인증된 설정 계약에 맞춘 서버
저장·적용 상태 분리, 그리고 사용자가 등록한 종목과 매수·매도 패턴의
완전한 관리 흐름이다. 검증되지 않은 초안을 엔진에 전달하지 않는다.
