# REBUILD-02 미확인 사항

2026-09-13. 내부 설계 선택과 실제 API 사실을 구별한다. 문서 작성은 완료할 수 있지만 아래 매핑이 해소되기 전 실제 주문 어댑터를 완료·활성화했다고 표시하지 않는다. 이번에는 API 호출·주문·배포를 하지 않았다.

## 공식 근거와 한계

현재 보관본은 국내 주식 Qt/ActiveX OpenAPI+의 SendOrder를 사용한다. REST API와 해외파생 OpenAPI-W를 근거로 대신 적용하지 않는다. 공식 [OpenAPI+ 개발가이드 v1.7](https://download.kiwoom.com/web/openapi/kiwoom_openapi_plus_devguide_ver_1.7.pdf)의 16쪽에서 주문 유형과 원주문번호 입력, 42쪽에서 체결번호 FID909와 체결 관련 필드, 43쪽에서 주문가능수량 FID933의 존재를 확인했다. 이 필드 목록만으로 번호 유일성, 이벤트 순서, 예약 반영 관계가 증명되지는 않는다. 설치된 OCX·KOA Studio 버전의 규격과 대조해야 한다.

## 확정된 선택

수량 증액 정정 미지원, 요청/주문 상태 분리, signed 정정 증감량, 실제 체결 기반 관리 원장, 의무별 예약, 계좌당 지정 PC·단일 dispatcher, UNKNOWN 자동 재전송 금지, 외부 보유 자동 편입 금지, 시간 기반 잔고 보정 금지를 채택한다. 상위 계획과 증액 지원 충돌은 발견하지 않았다.

## 검증 상태

문서의 수량·예약·제출 기대값은 매트릭스 하단 검산 결과를 따른다. 실제 엔진 테스트·실계좌 검증·모의계좌 API 검증·배포 검증은 모두 미수행이다. API 근거 확보는 문서 검산 통과로 대체할 수 없다.
