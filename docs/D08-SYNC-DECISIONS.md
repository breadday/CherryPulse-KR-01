# D08 동기화 결정 기록

- 작성일: 2026-10-11 (사용자 결정)
- 상태: 제품 선택 3건과 세부 정책 5건 확정. 실제 Supabase 인증·연동은 미착수다.

## 확정 결정

1. 클라우드 DB: Supabase (원하는 설정·명령 전달용)
2. 로그인: Supabase Auth
3. 명령 수신 경로: Windows 엔진의 주기적 폴링

## 결정의 의미와 한계

- 위 3건은 제품 선택 결정이며, 프로젝트 URL·anon key·service key 등 비밀값은
  저장소에 기록·커밋하지 않는다. `.env`·토큰·운영 DB를 문서에 복사하지 않는다.
- 세부 폴링·충돌·권한·순번·보존 정책은 2026-10-12에 확정했으며 아래에 기록한다.
- Telegram을 외부 알림 채널로 선택했다. 개인 채팅의 봇 토큰/채팅 ID 설정과
  송신기 구현은 대기 중이다. 실제 Supabase 프로젝트/credential도 미정이다.
  로컬 가상 sync는 개발할 수 있지만 실제 연동을 활성화하지 않는다.
- 실제/모의 주문 API 호출, 운영 DB 변경, 배포는 별도 명시적 지시 없이 수행하지
  않는다.

실제 인증·네트워크 연결 전에는 가상 전송 경계에서 유지한다.

## 2026-10-12 세부 정책 확정

사용자 확정값은 [D08 폴링 계약](D08-POLLING-CONTRACT.md)과
[진행 현황/질문서](PROJECT-STATUS-AND-DECISIONS.md)에 반영한다.

- 주기 5초·timeout 3초. 네트워크/5xx/timeout만 최대 5분 지수 백오프, 4xx는 재시도 없이 운영자 확인.
- 서버 단조 증가 순번과 `expected_version` 일치 시 적용. 충돌·역순·오프라인 지연 명령 자동 병합 금지.
- 본인만 접근, 사용자 관리화면에서 권한 변경. `auth.uid() = owner`와 명시적 계좌·환경 연결을 강제하고 기본 거부. 감사 이력 1년(법규상 연장 가능).
- outbox는 HTTP 200 및 순번 반영 ACK 전 삭제 금지. ACK 후 원장 7일, 압축 보관 30일; 순번을 멱등키로 사용.
- 마지막 동기화 5분 보드 경고, 30분 운영자 알림 기준. 엔진 상태 불명은 오프라인 표시, 폴링 성공 전 하향 명령 적용 금지.
- Telegram 채널은 선택됐지만 봇 토큰/채팅 ID가 로컬에 설정되지 않아 외부 송신은 아직 불가하다. 로컬 동기화 계약/가상 구현은 가능하다.

이 결정은 Supabase 프로젝트 생성·schema/RLS 적용·계정 인증이나 네트워크 연동을 실행한 기록이 아니다.
