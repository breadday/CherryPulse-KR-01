# CherryPulse-KR-01 개발 계획

> 최신 실제 현황은 [`PROJECT_STATUS_2026-09-11.md`](PROJECT_STATUS_2026-09-11.md)를 기준으로 한다. 이 문서는 장기 개선 순서와 완료 기준을 유지한다.

- 작성일: 2026-09-10
- 기준 브랜치: `main`
- 계획 반영 브랜치: `automation/opencode-herdr-pipeline`
- 목표: 종목선정은 외부 시스템에 맡기고, CherryPulse는 트레이딩 실행·위험관리·주문 상태관리 시스템으로 발전시킨다.
- 운영 원칙: 실계좌 전환보다 손실 방지와 재현 가능한 검증을 우선한다.

## 1. 현재 판단

현재 프로젝트는 다음 흐름을 가진 MVP 단계다.

```
일봉 후보 생성
  → 전략별 유니버스 분배
  → 장중 감시
  → 리스크 검사
  → 키움 주문·체결
  → SQLite·텔레그램 기록
```

기능 흐름은 연결되어 있지만 다음 위험이 남아 있다.

- 내부 전략과 외부 종목선정의 책임 경계가 명확하지 않다.
- 손절이 일반 자동매도·전략·뉴스·일봉 캐시와 같은 실행 흐름에 묶일 가능성이 있다.
- 장 마감 전 stale data와 reconnect 정책이 손절 감시를 중단시킬 수 있다.
- 손절 감지와 미체결 재주문 상태가 메모리에만 남으면 재시작 시 복구가 어렵다.
- 자동 회귀 테스트와 CI가 부족하다.
- 모의투자에서 충분한 운영 증거를 만들기 전에는 실계좌 사용을 판단할 수 없다.

## 2. 목표 구조

```
외부 종목선정 시스템
  → candidate.json 또는 SQLite 입력
  → ExternalCandidateProvider
  → CherryPulse Trading Engine
       ├─ RiskGuard: 보유 포지션 위험 감시
       ├─ Strategy/Entry: 신규 진입 판단
       ├─ OrderExecutor: 주문·취소·재주문
       ├─ Position/Reconciliation: 계좌와 내부 상태 대조
       └─ EventStore/Alert: 상태 영속화와 긴급 알림
  → 모의투자 검증
  → 승인된 경우에만 실계좌 전환 검토
```

핵심 우선순위는 다음과 같다.

1. 이미 보유한 종목에서 더 큰 손실이 발생하지 않도록 한다.
2. 손절 경로는 전략 성공 여부와 무관하게 동작해야 한다.
3. 주문 상태를 재시작 후 복구할 수 있어야 한다.
4. 모든 위험 판단을 테스트와 로그로 재현할 수 있어야 한다.
5. 종목선정 기능은 외부 입력으로 교체 가능하게 만든다.

## 3. 개발 단계

### Phase 0 — 자동개발 환경 검증

목표: ChatGPT가 만든 명세를 Herdr/OpenCode가 복사·붙여넣기 없이 처리하는지 확인한다.

작업:

- `opencode.jsonc` 권한 설정 검증
- analyzer → implementer → tester → reviewer 순서 검증
- `docs/agent-handoff/` 산출물 생성 확인
- `main`, `.env`, 브로커 전송 파일, live trading 변경 차단 확인
- TASK-001을 자동화 runner로 1회 실행

완료 기준:

- 각 단계가 독립 로그를 남긴다.
- reviewer가 PASS가 아니면 push하지 않는다.
- 실패 시 어느 단계에서 중단되었는지 확인할 수 있다.
- 실제 키움 주문이 발생하지 않는다.

중단 기준:

- OpenCode가 허용 범위 밖의 파일을 수정한다.
- 안전검사가 우회된다.
- 손절 관련 테스트 없이 PASS를 기록한다.

### Phase 1 — 현재 거래 흐름 기준선 고정

목표: 수정 전에 현재 동작과 위험 지점을 테스트로 고정한다.

작업:

- `engine.py`의 tick 처리 순서와 매도 경로를 호출 그래프로 기록
- `_auto_sell_allowed_now`, `_submit_auto_sell`, grace, trend hold의 관계 확인
- `main_live.py`의 stale data와 reconnect 시간 정책 확인
- 포지션·주문·미체결·재시작 상태 흐름을 테스트 fixture로 구성
- 기존 전략별 손절 기준을 문서화하고 임의로 변경하지 않는다

필수 산출물:

- `TASK-001-SPEC.md`
- 현재 동작 회귀 테스트
- 위험 경로 호출 순서 문서
- 테스트 실행 결과

완료 기준:

- 손절이 막힐 수 있는 모든 조건이 파일·함수·테스트로 추적된다.
- 수정 전 기준 테스트가 재현 가능하다.

### Phase 2 — RiskGuard 독립화

목표: 손절 감지를 전략과 분리한다.

작업:

- `core/risk_guard.py` 추가 또는 기존 리스크 모듈과 책임 조정
- 입력값은 최소한 종목, 현재가, 평균가, 보유수량, 위험 설정으로 제한
- 보유 포지션에 대한 손절 확인을 tick 처리의 최우선 경로에 둔다
- 일봉 조회, 뉴스 조회, 전략 신호, trend hold, 일반 매도 시간 제한과 독립시킨다
- 손절 전용 주문 제출 경로를 정의한다
- 기존 익절·부분매도 정책과 손절 정책을 분리한다

필수 테스트:

- 장중 손절
- 일반 자동매도 시간이 지난 뒤 손절
- 일봉 캐시 실패 중 손절
- 뉴스 조회 실패 중 손절
- grace 설정 중 손절
- trend hold 활성 중 손절
- 보유수량 0과 중복 손절 이벤트
- 가격·평균가 누락 또는 비정상값

완료 기준:

- 손절 판단이 전략 함수나 일봉 캐시에 의존하지 않는다.
- 손절 주문에는 일반 자동매도 시간 제한이 적용되지 않는다.
- 동일 포지션에 중복 주문이 발생하지 않는다.

### Phase 3 — 주문 상태와 재시작 복구

목표: 감지 후 주문이 실패하거나 프로세스가 재시작되어도 위험 상태를 잃지 않는다.

작업:

- `risk_events` 또는 동등한 이벤트 저장 구조 추가
- 상태 정의:
  - `STOP_DETECTED`
  - `SELL_SUBMITTING`
  - `SELL_PARTIAL`
  - `SELL_FILLED`
  - `MANUAL_INTERVENTION_REQUIRED`
- 주문 요청 ID와 broker 주문 ID 연결
- 미체결 취소 → 재주문 정책에 timeout과 최대 시도 횟수 추가
- 시작 시 계좌 보유내역과 저장된 위험 이벤트를 대조
- 동일 주문 재전송 방지용 idempotency key 추가

필수 테스트:

- 주문 거절
- timeout
- 부분 체결
- 미체결 취소 실패
- 프로세스 재시작
- 저장소 기록 실패
- 이미 청산된 종목의 중복 이벤트

완료 기준:

- 재시작해도 손절 진행 상태를 복구한다.
- 무한 재주문과 무한 대기 루프가 없다.
- 수동 개입이 필요한 상태가 Telegram과 로그에 남는다.

### Phase 4 — 외부 종목선정 입력 분리

목표: CherryPulse가 종목을 직접 선정하지 않고 외부 후보를 받아 거래만 수행할 수 있게 한다.

작업:

- `ExternalCandidateProvider` 인터페이스 정의
- 입력 스키마 정의:
  - symbol
  - name
  - selection_date
  - strategy_tag
  - intended_holding_period
  - source
  - expires_at
- JSON 파일 입력을 먼저 구현하고 이후 SQLite/API를 확장한다.
- 입력 유효기간이 지난 후보는 신규 진입에 사용하지 않는다.
- 보유종목 위험관리는 후보 입력과 무관하게 계속 실행한다.
- 기존 내부 종목선정 로직은 feature flag로 분리하고 기본값을 명확히 한다.

완료 기준:

- 외부 후보 파일이 없어도 보유종목 손절은 동작한다.
- 외부 후보만으로 모의투자 신규 진입 테스트가 가능하다.
- 후보 선정 로직과 매매 실행 로직을 독립적으로 교체할 수 있다.

### Phase 5 — 모의투자 운영 검증

목표: 코드 테스트를 넘어 실제 운영 조건에서 안전성을 확인한다.

검증 기간:

- 최소 20거래일 또는 손절·재접속·부분체결·재시작 사례가 충분히 발생할 때까지

수집 지표:

- 손절 감지 지연 시간
- 손절 주문 제출 지연 시간
- 감지 후 미체결 비율
- 재주문 횟수
- stale data 지속 시간
- reconnect 성공률
- 내부 포지션과 계좌 잔고 불일치
- 중복 주문 수
- 수동 개입 발생 횟수
- 전략별 손익과 최대 손실

완료 기준:

- 치명적 중복 주문 0건
- 손절 누락 0건
- 재시작 후 상태 복구 성공
- 모든 수동 개입 사례 원인 기록
- 실계좌 전환 여부를 별도 판단 문서로 승인

### Phase 6 — 실계좌 전환 검토

실계좌 전환은 개발 완료의 자동 결과가 아니다. 다음 조건을 모두 검토한 뒤 별도 승인한다.

- 모의투자 운영 검증 완료
- 손절 누락·중복 주문·상태 불일치가 해결됨
- 브로커 장애와 네트워크 장애 복구 절차 확인
- 주문 금액과 일일 손실 한도 설정
- 긴급 중지 스위치 확인
- 알림 수신 확인
- 소액·제한된 종목으로 단계적 전환 계획 수립

## 4. 작업 순서와 담당 역할

| 역할 | 책임 |
|---|---|
| ChatGPT | 요구사항 정리, 설계, acceptance criteria, 위험 검토 |
| analyzer | 현재 코드 조사, 구현 명세 작성 |
| implementer | 명세에 따른 최소 코드 수정 |
| tester | 자동 테스트와 실패 경로 실행 |
| reviewer | diff·테스트·거래 안전성 독립 검토 |
| 사용자 | 모의투자 승인, PR merge, 실계좌 전환 승인 |

사용자는 매 단계의 코드를 복사·붙여넣기할 필요가 없다. 다만 실거래와 main merge는 자동 승인하지 않는다.

## 5. TASK 실행 순서

권장 순서:

1. TASK-000: 자동화 runner smoke test
2. TASK-001: RiskGuard 독립화
3. TASK-002: 손절 우선순위와 시간 제한 회귀 테스트
4. TASK-003: stale data/reconnect 감시 보강
5. TASK-004: risk event 영속화와 재시작 복구
6. TASK-005: 외부 후보 입력 인터페이스
7. TASK-006: 주문 취소·재주문·부분체결 상태기계
8. TASK-007: 모의투자 운영 대시보드와 지표
9. TASK-008: 실계좌 전환 검토 문서

각 TASK는 다음 파일을 남긴다.

```
docs/agent-handoff/TASK-xxx-SPEC.md
docs/agent-handoff/TASK-xxx-IMPLEMENTATION.md
docs/agent-handoff/TASK-xxx-TEST.md
docs/agent-handoff/TASK-xxx-REVIEW.md
```

## 6. 공통 완료 조건

모든 작업은 아래 조건을 만족해야 한다.

- 변경 범위가 TASK 명세와 일치한다.
- 관련 테스트가 존재하고 실제로 실행되었다.
- 실패 경로가 최소 1개 이상 검증되었다.
- `git diff --check`가 통과한다.
- 비밀값과 `.env`가 변경되지 않았다.
- 실거래 활성화 코드가 추가되지 않았다.
- 브로커 주문 전송 파일 변경은 별도 승인되었다.
- reviewer가 `PASS`를 기록했다.
- main merge 전 사람이 변경 내용을 확인한다.

## 7. 지금 바로 실행할 다음 작업

현재 우선순위는 새 전략 추가가 아니라 비밀값 정리, live 이중 잠금, 로그인 timeout, 모의투자 운영 증거 축적이다. 테스트와 snapshot 검증은 이미 기본 회귀 경로에 들어갔다.

일일 검증 명령은 다음과 같다.

```powershell
py -3.8-32 validate_daily_snapshot.py
py -3.8-32 -B -m pytest -q
```

실계좌 전환이나 `-AutoPublish`는 별도 승인 없이는 진행하지 않는다.

> 목표는 수익을 보장하는 시스템이 아니다. 먼저 손절 누락, 중복 주문, 상태 유실이라는 치명적 실패를 제거하고, 그 다음 전략 수익성을 검증한다.
