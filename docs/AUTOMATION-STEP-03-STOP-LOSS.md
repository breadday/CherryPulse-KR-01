# AUTOMATION STEP 03 — 손절 우선 실행 흐름

- 검증일: 2026-09-22
- 작업 브랜치: `feat/automated-rebuild-20260921`
- 실행 범위: 내부 SQLite 원장과 가상 어댑터
- 실계좌·실주문: 사용하지 않음

## 구현 범위

- `StopLossTriggered`를 검증 가능한 내부 증거로 기록한다.
- 관측 가격이 손절 임계 가격 이하이고 가격이 모두 양수일 때만 트리거를 허용한다.
- 트리거의 설정 버전이 현재 적용 버전과 다르면 `STALE_CONFIG_VERSION`으로 거절한다.
- 트리거가 원장에 기록되면 해당 종목의 신규 진입을 차단하고 청산 상태를 유지한다.
- 확인된 관리 보유수량만 SELL `MARKET` 청산 대상으로 삼는다.
- 손절 트리거 뒤 늦게 도착한 BUY 체결도 같은 청산 의무에 포함한다.
- 동일 이벤트 재처리, 기존 예약 수량, 미해결 SELL, 수량 불일치 상태에서는 중복 또는 과다 청산 주문을 만들지 않는다.
- 기존 원장, projection, idempotency, UNKNOWN·대조 필요 상태를 재사용한다.

## 제외 범위

- 실제 증권사 API, 실계좌 인증, 실주문 전송
- 외부 시세 수신기와 손절 가격 계산기
- 키움·나무 통합과 가격밴드 분할매매
- 별도 주매매건 아이디어의 설계·개발

## RED → GREEN 근거

`StopLossTriggered`와 처리 경로가 없어 처음엔 모든 신규 테스트가 실패했다. 증거 모델, 검증, projection, 가상 dispatcher를 최소 구현한 뒤 독립 검토에서 발견된 우회 경로와 다음 시나리오를 추가로 회귀 테스트로 묶었다.

1. 부분 BUY 체결 수량만 시장가 청산하고 동일 트리거 재처리는 중복 처리하지 않는다.
2. 손절 트리거 이후 늦은 BUY 체결도 추가 청산 의무에 포함한다.
3. 미해결 SELL이 있으면 중복 SELL을 제출하지 않는다.
4. 수량 불일치가 있으면 확인되지 않은 수량을 매도하지 않는다.
5. 임계값을 충족하지 않은 손절 입력을 거절한다.
6. 오래된 설정 버전의 손절 입력을 거절한다.
7. 전송되지 않았음이 증명된 과거 SELL 실패가 현재 손절 청산을 영구 차단하지 않는다.
8. `Ledger.ingest()`·`ingest_json()`으로 직접 들어온 손절·늦은 BUY 체결도 등록된 가상 dispatcher가 즉시 drain한다.
9. 세션 대조 승인 전 drain 실패 후 동일 트리거 재처리는 커밋된 의무를 다시 drain한다.
10. drain 도중 설정 버전이 바뀌어 전송이 실패해도 동일 트리거 재처리는 현재 버전의 청산 주문을 생성한다.
11. 청산 의도 영속화 후 전송 직전에 설정 버전이 바뀌면 미전송 증거로 기존 의도를 종료한 뒤 현재 버전으로 다시 청산한다.
12. 이미 영속화되었지만 아직 전송되지 않은 청산 요청도 동일 트리거 재처리에서 먼저 전송한다.

## 독립 검토

1차 독립 검토에서 다음 두 논리 결함을 재현해 실패했다.

- 과거에 전송되지 않았음이 증명된 SELL 실패까지 현재 손절 청산을 영구 차단했다.
- `VirtualDispatcher.process()` 대신 공개 원장 입력 경계(`Ledger.ingest`, `ingest_json`)만 사용하면 손절 drain이 실행되지 않았다.

각 결함을 재현하는 RED 테스트를 추가했다. 과거에 settled된 실패에 대한 전역 차단을 제거하고, 사실이 커밋된 뒤 등록된 handler가 호출되도록 수정했다.

2차 독립 검토에서 handler 실행 전에 사실이 이미 커밋되므로 세션 미승인이나 설정 버전 경합으로 handler가 실패하면 동일 이벤트 재처리가 조기 반환되어 청산 의무가 고립되는 결함을 재현했다. 두 실패 경로를 RED 테스트로 추가하고, 정확히 동일한 이벤트 재처리는 사실을 중복 기록하지 않으면서 등록된 handler를 다시 실행하도록 수정했다.

3차 독립 검토에서 청산 요청을 영속화한 직후 `send()` 전 설정 버전이 바뀌면 stale 요청의 예약 때문에 재처리도 멈추는 경합을 재현했다. 해당 경로를 RED 테스트로 추가하고, 전송 전 freshness 검사에서 stale이 확인된 청산 요청은 `NOT_INVOKED` 증거로 종료한 뒤 현재 설정 버전으로 새 청산 의무를 drain하도록 수정했다. 이미 영속화됐지만 아직 전송되지 않은 청산 요청도 동일 트리거 재처리에서 먼저 전송하도록 회귀 테스트를 추가했다.
