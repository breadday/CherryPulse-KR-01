## 2. 멱등성·정규화·원자성

범위는 `(broker_adapter, account_id, environment, execution_scope, idempotency_key)`. 환경은 LIVE/PAPER, 실행 범위는 안정적인 execution UUID 또는 명시적 ACCOUNT 범위다. 요청 종류는 내용에 포함하므로 같은 키로 다른 종류 요청도 충돌이다. 재시작·날짜 변경으로 키를 초기화하지 않는다. 키는 대소문자 구별 비어 있지 않은 ASCII, 공백은 자동 제거하지 않고 거절한다. 이력 이관 후에도 키·내용 tombstone을 보존한다.

공통 의미 비교에는 계좌·환경·실행 범위·요청 종류·종목·방향·수량·가격·주문 조건·설정 버전을 포함한다. 정정·취소는 대상 client_order_id, 대상 broker link/version, 변경 내용 또는 취소 수량까지 포함한다. 서버 생성 ID와 전송 시각은 제외하되 정정·취소의 대상 ID는 제외하지 않는다.

- 수량: 주 단위 정수. 신규/취소는 양수, 정정은 signed qty_delta. bool·float·문자 수량은 거절.
- 가격: 통화·최소 단위가 정해진 정규 십진 문자열. `10000.00`→`10000`. 이진 float·지수·쉼표 표기 거절. 호가 단위는 Q10.
- 시장가: 내부 price=null, 생략도 null. 입력 0·양수는 거절. 어댑터 0 변환은 별도.
- 지정가: 양수 가격 필수, 생략/null 거절.
- 정정 patch: 생략은 유지, 명시 null 가격은 거절. 가격만 변경할 때 qty_delta 생략은 0.
- 취소: cancel_qty 필수. 생략/null을 전량으로 해석하지 않음. 전량 명령은 원장 버전에서 수량을 해석해 요청에 고정.
- 주문 조건: 허용 enum·거래 세션·유효 조건 포함. 명세 없는 기본값은 만들지 않음. 코드·계좌는 마스터/내부 ID로 정규화.

정규화 버전·JSON·digest를 저장한다. 같은 범위·키·같은 내용은 기존 request_id·상태·결과 반환. 다른 내용은 CONFLICT_IDEMPOTENCY_MISMATCH, 추가 실행·예약·API 0. 해시뿐 아니라 정규화 내용도 비교한다.

한 로컬 쓰기 트랜잭션에서 권한·버전·수량 검증, 멱등성 확인, 요청 기록, 예약을 수행한다. 범위+키 UNIQUE, request_id PK, 의무별 예약 제약으로 동시 요청을 직렬화한다. 경쟁 패자는 기존 내용을 재비교한다. 네트워크 조회·API 전송은 트랜잭션 밖이다. 단일 dispatcher가 별도 짧은 트랜잭션으로 SENDING을 저장한 뒤 호출한다.

## 3. 요청 상태와 주문 상태

요청 전송 상태와 논리 주문 생명주기는 분리한다. 전송 시도는 request_attempts에 남긴다. 로컬 미지원은 별도 decision=REJECTED_UNSUPPORTED이며 transport=INTENT_PERSISTED 감사 기록만 남길 수 있다. 실행 큐·미확정 전송 집계에는 포함하지 않는다.

| 전송 상태 | 의미 | 허용 전이·근거 |
|---|---|---|
| INTENT_PERSISTED | 로컬 의도 기록, 아직 미호출 | SENDING; 명확한 미호출 장애는 SEND_FAILED; 로컬 거절/만료 decision은 전송 안 함 |
| SENDING | 호출 직전 내구성 기록, 실제 호출 여부는 모호할 수 있음 | SENT, ACKED, UNKNOWN, 명확한 미전송만 SEND_FAILED, 상관된 거절은 REJECTED_BY_BROKER |
| SENT | 호출 반환 기록, 접수 보장은 아님 | ACKED, REJECTED_BY_BROKER, UNKNOWN, 재시작 시 RECONCILING |
| ACKED | 해당 요청 접수 증거 있음 | 전송 상태 종결. 취소/정정 효과는 별도 effect_state로 계속 추적 |
| SEND_FAILED | 미전송이 명확한 근거로 확인됨 | 종결. 정책 허용 후속 의도는 새 키·request_id로 연결 |
| UNKNOWN | 전송/결과 불명 | RECONCILING, 명확한 지연 증거로 ACKED 또는 REJECTED_BY_BROKER |
| RECONCILING | 주문·체결·미체결·잔고 대조 중 | 증거로 ACKED/REJECTED_BY_BROKER/SEND_FAILED, 미해결이면 UNKNOWN |
| REJECTED_BY_BROKER | 해당 요청의 거절 확인 | 종결. 원주문은 별도 상태 유지 |

취소·정정 effect_state는 PENDING/CONFIRMED/REJECTED/UNKNOWN이다. 취소 ACKED는 예약 해제나 취소 완료를 뜻하지 않는다. 조회에 없다는 이유로 SEND_FAILED를 만들지 않는다. UNKNOWN은 자동 재전송하지 않는다. 재시작 시 SENDING→UNKNOWN→RECONCILING, SENT→RECONCILING, 효과 미확정 ACKED·연결 미완료·모든 잠재 미확정 요청도 대조한다. INTENT_PERSISTED만 명확한 미호출 경계를 확인한 뒤 재개 가능하다.

| 주문 생명주기 | 의미·전이 |
|---|---|
| PENDING | 활성 여부 미확정. 증거에 따라 OPEN/부분체결/전량체결/취소/거절로 이동 |
| OPEN | 접수·활성 잔량 확인, 체결0. PARTIALLY_FILLED/FILLED/CANCELLED |
| PARTIALLY_FILLED | 일부 체결·잔량 있음. FILLED 또는 CANCELLED |
| FILLED | 유효 수량 전량 체결·잔량0. 지연 접수로 활성 상태 회귀 금지 |
| CANCELLED | 확인된 잔량 취소·활성잔량0. 양립하는 지연 체결 반영 후에도 유지 |
| REJECTED | 신규 주문의 명확한 거절. 정정·취소 거절로 원주문을 거절 처리하지 않음 |

대조 상태 OK/RECONCILIATION_REQUIRED/RECONCILING은 독립이다. 종결 상태와 모순되는 새 증거는 무시하지 않고 원문·대조 이력을 남긴다. 접수보다 먼저 관측한 체결도 처리하는 방어적 테스트를 둔다. 검증된 식별자로 연결 가능하면 먼저 반영하고, 불명확하면 원문을 보존·격리·대조하며 종목/가격만으로 임의 연결하지 않는다.

## 4. 수량 보존·예약

집계 단위는 하나의 논리 주문과 연결된 정정 주문 전체다.

`Q0 + D = F + C + A`

Q0=최초수량, D=확인된 정정 증감 합, F=중복 제거 누적 체결, C=확인 취소수량, A=활성 잔량. 가격 정정은 D0. 감액100→80은 D-20이며 C에 중복 가산하지 않는다. 정정/취소 접수만으로 수량을 확정하지 않는다. 원본 이벤트를 보존하고 검증된 매핑으로 변환한다.

미확인 A는 null과 마지막 확인값으로 구분한다. 취소 확인 후 지연 체결 전에는 관측 수량 gap이 생길 수 있다. `gap=Q0+D-F-C-A`를 남기고 RECONCILIATION_REQUIRED로 둔다. 임의 F/C/A 생성 금지. 같은 고유 이벤트 집합은 도착 순서가 달라도 같은 최종 수량으로 수렴해야 한다. 로컬 거절 의도는 증권사 활성 주문이 아니므로 가짜 취소량으로 식을 맞추지 않는다.

예약은 실제 매도 의무별 한 번이다. 제출 전부터 예약한다. 취소 요청은 추가 예약0·요청 시 해제0. 매도100 예약 후30 체결이면 보유30 감소·예약70. 감액은 확인 전 예약 유지, 확인 후 감소분만 해제. 취소 확인도 확인된 수량만 해제하고 미해소 노출 예약은 유지한다.

수량 증액 정정은 초기 미지원(REJECTED_UNSUPPORTED), 추가 예약0·API0. 기존 계획에 증액 지원 확정은 없어 충돌 없다. 향후 지원 시 증가분 선예약·UNKNOWN 동안 유지·명확한 거절 시 증가분 해제가 필요하다.

증권사 매도가능량에 반영된 예약은 재차 차감하지 않는다. 조회 필드 의미와 특정 예약 반영 여부를 각각 확인한다. 확인된 경우만 `broker_available - 미반영 로컬 노출`과 `managed_qty - 관리 예약`의 작은 값으로 추가 수량을 제한한다. 불명확하면 대조한다.

체결 중복 방지·체결 원장·포지션/배정·예약 소비·보호 등록·청산 의무·outbox는 하나의 트랜잭션이다. 중복 수신 원문 로그는 남겨도 도메인 추가 반영과 제출은0이다. 종료 후 지연 체결도 반영하며, 취소70+체결30=최초100이면 CANCELLED를 유지한다. 취소100 확인 뒤 체결30이면 취소를70으로 조용히 줄이지 않고 대조한다.

## 5. 관리·보호·청산 명령

대조 정상 시 계좌 보유=관리 배정 합+미배정 외부 보유. 실제 관리량은 초기 명시 배정+관리 매수 체결-관리 매도 체결±근거 있는 배정 이전이다. execution_configs 또는 매도 제출로 관리량을 변경하지 않는다. 수동 보유는 명시적 편입 없이 관리 청산하지 않는다.

부분 매수 체결과 동시에 보호 대상으로 기록하되 실제 매도 제출은 별도다. 이미 청산 발동 시 추가 체결은 추가 청산 의무로 기록한다. 판단 주체가 여럿이어도 예약·제출은 단일 직렬 경로다. 보호는 신규 진입 제한을 우회하지만 계좌·수량·예약·UNKNOWN·불일치 검증을 우회하지 않는다.

| 명령 | 의미 |
|---|---|
| ENTRY_STOP | 범위 내 신규 진입 차단, 기존 주문 자동 취소 아님, 보유 보호 유지 |
| CANCEL_OPEN_BUYS | 매수 잔량 취소 요청, 추가 체결 추적 유지. 단독 영구 진입 중지 아님 |
| LIQUIDATE_MANAGED | 진입 차단+관련 매수 취소 요청+관리분 청산+추가 체결 추적 |
| LIQUIDATE_ACCOUNT | 명시적 계좌 전체 청산 권한·범위. 관리 청산과 구별하며 외부 보유 포함 의도 기록 |

청산 완료는 관리량0 AND 관련 미체결0 AND 관련 미확정 요청0이며 대조 정상이어야 한다. ACKED라도 효과 미확정이면 완료 불가. 뒤늦은 새 체결이 확인되면 완료 이력을 지우지 않고 의무 재개. 매수 취소 UNKNOWN 중에도 확인된 비중복 관리 보유 매도는 가능하지만 관련 매도 UNKNOWN·수량 불일치에는 추가 제출 차단.

명령도 멱등성·기대 버전·만료·권한을 검사한다. 엔진 수락 전에는 반영 대기다. 새 패턴 버전 수락 전까지 기존 보유 보호 규칙을 유지한다.

## 6. 조회·외부 거래·잠금

query_started_at/query_finished_at/local_event_seq_at_start/finish, query_id, 페이지·오류를 기록한다. 동일 시점 증권사 스냅샷 보장은 아니다. 조회 중·조회 후 지연 이벤트와 대조하고 불일치 시 재조회한다. 주문·체결·미체결·잔고를 함께 확인하며 조회 실패/페이지 누락을 빈 결과로 해석하지 않는다.

확인된 외부 체결은 external_fill, 설명 안 되는 잔고 차이는 RECONCILIATION_REQUIRED다. balance_adjustment는 근거·승인자·시각·수량·사유를 갖는 별도 보정이다. 가상 체결 생성과 시간 경과에 따른 자동 보정 금지. 외부·관리 배정 구분을 유지하고 외부 매도로 어떤 배정이 감소했는지 불명확하면 임의 할당하지 않는다.

초기 계좌당 지정 Windows PC 한 대. 주문 활성 전 계좌·환경 OS 잠금을 획득하고 종료까지 유지한다. 잠금 실패 READ_ONLY는 주문·예약·활성 실행 세션을 변경하지 않는다. heartbeat 만료로 잠금을 탈취하지 않는다. 비정상 종료 후 잠금 획득이 가능해도 계좌 대조 전 주문 재개 금지. 다른 PC는 로컬 잠금이 보호하지 않는다.

### 멱등성 검사 순서 보충

입력 형식·인증·범위 확인 후 정규화한다. 같은 범위의 기존 키가 있으면 현재 주문 잔량에 따른 업무 검증보다 먼저 내용 일치/충돌을 판단한다. 이 순서로 T10의 다른 대상 취소는 기존 키 충돌을 반환한다. 키가 없을 때만 현재 버전·수량·여력 검증과 예약·요청 생성을 같은 트랜잭션에서 수행한다. 인증·범위 검사를 생략하거나 다른 사용자의 키 존재를 노출하지 않는다.

### 내부 구현의 현재 범위 — 2026-09-14

SQLite journal과 가상 이벤트 검사를 추가했다. [구현 기록과 미구현 경계](REBUILD-04-LOCAL-LEDGER.md)를 함께 읽는다. 본 계약의 실제 증권사 연결·요청 실패/거절 전체 상태·계좌 잠금·웹 명령 인증까지 구현됐다는 뜻은 아니다.

## 2026-09-15 가상 구현 보충

미전송이 입증되거나 신규 주문이 거절되어 성립하지 않은 경우 예약은 해제하되 취소 수량을 생성하지 않는다. 수량 항등식 차이는 적용 불가로 표시한다. 취소·정정의 거절은 원주문 수량을 해제하지 않는다. 모순된 지연 체결은 보존하여 대조를 요구한다. 새 계좌 잠금 획득마다 가상 시작 게이트를 닫고 최신 원장 검토 후 연다. 실제 증권사 대조나 명령 인증을 대신하지 않는다. [상세 구현·제약](REBUILD-04-REQUEST-FAILURES-AND-LOCK.md).

## 로컬 가상 명령 유효성 구현

요청 접수와 전송 직전에 expires_at 및 현재 적용 config_version을 검사한다. 같은 키의 유효 기한 변경은 내용 충돌이며 동일 내용 재조회는 기한을 연장하지 않는다. config 사실은 로컬 원장과 outbox에 기록한다. 초기 가상 버전 1 및 기한 생략의 범위, 예약 유지·외부 인증 미구현 제한은 [구현 기록](REBUILD-04-COMMAND-FRESHNESS.md)을 따른다.

## 로컬 미전송 의도 폐기

최신 원장 검토에 근거한 명시적 폐기는 미호출 증거를 기록하고 요청을 보존한다. 신규 매도 예약만 해제하며 증권사 취소량을 생성하지 않는다. 전송·체결 증거가 있는 요청은 폐기 불가다. [멱등성·제약·검증 기록](REBUILD-04-DISCARD.md).

## 가상 불일치 해소 근거

RECONCILED는 특정 불일치 ID·종목과 최신 원장 revision·동일한 관리 수량을 확인한 가상 검토 사실이다. 원래 증거를 보존하며 수량을 조정하지 않는다. 다른 불일치·주문 충돌·미확정 요청은 이를 통해 해소하지 않는다. [조건과 실제 적용 제한](REBUILD-04-RECONCILIATION.md).

## 가상 체결 격리 구현

연결 불명확 가상 체결은 수량 미반영·종목 대조 상태로 보존한다. 유일한 ACK 주문번호 연결과 종목 일치를 확인한 뒤 체결과 해제 근거를 원자적으로 기록한다. 실제 원문·체결 식별 규격은 별도 확인 대상이다. [구현과 제한](REBUILD-04-QUARANTINE.md).
