# Q12 매수 패턴 결정 질문지

- 작성일: 2026-10-11
- 근거: `docs/REBUILD-02-OPEN-QUESTIONS.md` Q12, `docs/CherryPulse-KR-01-Development-Direction.md` 6절, `docs/NEXT-DEVELOPMENT-PLAN.md` D01·D05, `docs/D02-BOARD-PROGRESS.md` 218줄(D02 남은 완료 조건)
- 용도: 매수 패턴 화면·계약을 만들기 전에 사용자가 결정해야 할 값을 모으는 질문지다. 이 파일은 명세가 아니며, 값을 채우기 전에는 매수 폼·매수 실행을 만들지 않는다.
- 상태(2026-10-11): 제안 13건, 확정 0건. 아래 `제안:`은 결정이 아니며 코드에 반영하지 않는다.

## 차단 정책

- 정해지지 않은 값을 코드 기본값으로 만들지 않는다. 모든 미기입 항목은 매수 패턴 폼·계약·가상 실행의 차단 사유로 남는다.
- 이 질문지에 답하는 것은 주문 실행 허가가 아니다. 실제/모의 주문 API 호출, 운영 DB 변경, 배포는 별도 명시적 지시 없이 수행하지 않는다.
- 손절(매도) 수치는 D01·D03에서 정한 범위(고정 가격·확인된 평균 매수가 대비 하락률, 시장가 우선)를 그대로 따른다. 여기서는 매수 값만 정한다.

## 1. 매수 관측 대상과 트리거

1.1 매수 조건이 보는 값은 무엇인가? (예: 최근 체결가, 최우선 매수/매도 호가, 봉 가격 — 해당 항목만 남기고 나머지는 지운다)
- 답변: [제안] 최근 체결가 (키움 실시간 FID 10) 단일 값 / 근거: `inspect_kiwoom_realtime.py`로 원문 확인 가능한 최소 단위이며, 호가/봉은 FID 원문 확보 전까지 차단 유지. 외부 선정 종목은 체결가 기준이 가장 해석 분쟁이 적음. [확정 아님]

1.2 기준값의 종류와 비교 연산은 무엇인가? (예: 고정 가격 이하, 지정가 대비 비율 — AND/OR 조합 포함)
- 답변: [제안] 고정 가격 이하 (`last_price <= buy_target_price`) 단일 조건. AND/OR 조합 없음 - 첫 버전. / 근거: Development-Direction 6절 "범용 스크립트보다 제한된 조건 스키마 먼저" 원칙, 고정 가격이면 평균가 대비 계산 없이도 D01 손절과 결합 검증 가능. 비율 조건은 D05에서 확장. [확정 아님]

1.3 조건 충족의 지속·재발동 규칙은 무엇인가? (예: 틱 즉시 1회, N초 유지, 발동 후 재진입 금지 시간)
- 답변: [제안] 틱 즉시 1회 발동, 발동 후 해당 명령 ID 소진. 지속 유지 조건 없음(N초 유지 불필요). / 근거: 부분체결·재시작 복구 계약(D02)에서 "신호와 주문 접수 구분"을 위해 발동은 1회로 고정해야 중복 주문 방지 로직 검증이 단순해짐. [확정 아님]

## 2. 시간 기준

2.1 틱 즉시 판단인가, 지정 시간봉 확정 후 판단인가? (봉이면 봉 종류·확정 시각)
- 답변: [제안] 틱 즉시 판단. 봉 확정 판단은 차단. / 근거: 봉은 데이터 준비 범위 확인 전이며 D03 가상 손절도 틱 기반으로 확정됨. 봉 도입 시 `D02-BOARD-PROGRESS`의 남은 조건이 또 늘어나므로 첫 버전은 틱으로 제한. [확정 아님]

2.2 주문이 허용되는 거래 시간은 무엇인가? (예: 정규장만 — D03 가상 손절은 정규장만으로 확정됨)
- 답변: [제안] 정규장 09:00 ~ 15:20만 허용. 동시호가(08:40~09:00, 15:20~15:30) 제외. / 근거: NEXT-DEVELOPMENT-PLAN D03 "정규장만 확정"과 동일. [확정 아님]

2.3 조건의 유효 시간과 재평가 주기는 무엇인가?
- 답변: [제안] 조건 유효는 당일 장중만. 재평가는 시세 수신 시마다(최대 1초 주기). 명령 자체는 만료 시각 `15:20`으로 둠. / 근거: D01 명령 만료·적용 버전 계약 - 당일 만료가 가장 안전한 초기값. [확정 아님]

## 3. 주문 행동

3.1 주문 방식은 무엇인가? (시장가/지정가 — 지정가면 호가 기준)
- 답변: [제안] 지정가, 기준은 `최근 체결가` 그대로. 시장가 사용 안 함. / 근거: 손절은 시장가 우선이지만 매수는 지정가로 둬야 슬리피지·즉시 체결로 인한 보호 등록 레이스를 줄일 수 있음. D05에서 호가 기준 확장 가능. [확정 아님]

3.2 수량 산정은 무엇인가? (주 수량/금액, 분할 여부, 1회 상한)
- 답변: [제안] 고정 1주, 1회 상한 1주, 분할 없음, 금액 상한 10만원(1주 가격 초과 시 주문 차단). / 근거: 첫 가상 실행 검증에서 부분체결·보호 연결을 최소 수량으로 검증해야 하며, "정해지지 않은 값 기본값화 금지" 위반 없이 가장 보수적. [확정 아님]

3.3 부분체결된 매수 잔량은 어떻게 다루는가? (유지/취소, 추가 체결 시 보호 연결은 D03 규칙을 따름)
- 답변: [제안] 잔량 60초 유지 후 취소. 추가 체결 시 D03 규칙(체결 수량만큼 보호 대상 즉시 등록, 잔여 취소 중 추가 체결은 보호 증량) 그대로 따름. / 근거: D03 체결 시점 버전 고정 원칙과 일치. [확정 아님]

## 4. 재진입 규칙

4.1 같은 종목의 재진입 금지 시간 또는 조건은 무엇인가?
- 답변: [제안] 같은 종목 당일 재진입 금지(1회 체결 후 당일 재매수 차단). / 근거: 중복 진입 방지 계약을 가장 단순하게 검증 가능. 30분 등 단축은 실거래 데이터 후 D05에서 조정. [확정 아님]

4.2 보유 중 추가 매수를 허용하는가? (허용이면 상한과 손절 버전 적용 규칙)
- 답변: [제안] 불허. 보유 중이면 신규 매수 조건 무시. / 근거: 피라미딩 허용 시 평균가 변경 → 보호 버전 재계산 정책이 필요해 D03 발동 유지 정책과 충돌. 첫 버전은 불허로 단순화. [확정 아님]

## 5. 미체결·거절·취소 대응

5.1 미체결 유지 시간과 그 뒤의 행동(유지/취소/재주문 조건·한도)은 무엇인가?
- 답변: [제안] 60초 유지 후 취소 시도. 취소 후 재주문 없음(수동 재명령 필요). / 근거: 손절 쪽 UNKNOWN 자동 재주문 금지 원칙과 동일하게 매수도 자동 재주문 금지해야 중복 주문 위험 없음. TEST-MATRIX의 재주문 금지 준수. [확정 아님]

5.2 거절·전송 실패 시 행동은 무엇인가? (손절과 같은 자동 재주문 금지 원칙을 매수에도 적용하는지 확인)
- 답변: [제안] 자동 재주문 금지. 전송 상태 `UNKNOWN`으로 두고 `주문내역+체결내역+잔고` 3종 대조로 확정될 때까지 동일 의도 재주문 차단. / 근거: D01 `INTENT_PERSISTED → UNKNOWN → RECONCILING` 계약을 매수에도 동일 적용. [확정 아님]

## 6. 손절 연계와 우선순위

6.1 매수 체결 직후 붙는 보호 규칙은 무엇인가? (D03의 체결 시점 버전 고정 원칙과 연결)
- 답변: [제안] 체결 시점 버전 고정. 보호는 D01 범위 내 2가지 중 하나를 명령 시점에 선택: A) 고정 가격 손절, B) 확인된 평균 매수가 대비 -3% 하락률. 첫 제안은 B) -3%. / 근거: D01·D03에서 확정한 "고정 가격·평균가 대비 하락률, 시장가 우선" 범위 내. -3%는 테스트용 보수치, 수익 평가 목적 아님. [확정 아님]

6.2 손절과 매수 조건이 겹치면 무엇을 우선하는가? (기본안: 보호 손절 우선 — 확정 필요)
- 답변: [제안] 보호 손절 우선. 보유 수량이 있으면 매수 조건은 평가하지 않음. / 근거: NEXT-DEVELOPMENT-PLAN D05 "보호 청산 우선, 중복 매도 방지" 원칙을 매수/매도 충돌에도 동일 적용. [확정 아님]

## 답변 작성 방법

- 각 `답변: [미기입]`을 값으로 바꾸고, 근거(화면·문서·구두 결정 일시)를 함께 적는다.
- "나중에 정함"은 미기입으로 남긴다. 비워 둔 항목이 있으면 해당 범위의 폼·실행은 차단 상태로 둔다.
- 전부 기입되면 다음 순서로 진행한다: 매수 패턴 화면(D02) → 조건·주문 계약(D05) → 가상 시나리오 검증 → 결과 문서 기록.

## 아직 연결하지 않는 것

- D01 인증·desired/accepted/applied 적용 연결, D03 자동 시세·검증 세션, D06 키움 읽기 전용 근거, D07 실제 주문 경계는 이 질문지와 무관하게 차단 상태로 둔다.
- 물리 모바일 확인(D02 남은 조건)은 별도 체크리스트로 진행한다.
