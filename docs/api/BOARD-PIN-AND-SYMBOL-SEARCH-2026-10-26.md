# 개인용 4자리 비밀번호·종목명 코드 검색

## 최신 사용자 결정

사용자는 개인 전용 보드에서 이메일 가입·인증 대신 숫자 4자리 비밀번호만
입력하도록 요청했다. 앞선 이메일 UI 개선 중 이 결정을 반영했다.
이 문서는 이메일 인증 흐름을 설명하는 이전 인계 기록보다 우선한다.

## 변경

- 화면에는 4자리 비밀번호와 **보드 열기**만 표시한다. 이메일·가입·인증 버튼 제거.
- 숫자 4자리 입력 검사 → 확인 중 표시 → 성공·오류·잠금 사유를 상태 영역에 표시.
  입력 검사 전에 필드를 비활성화하던 흐름도 수정했다.
- 새 비밀번호는 무작위로 발급해 DB에 bcrypt 해시로만 설정했다. 실제 비밀번호는
  소스·마이그레이션·문서에 기록하지 않고 사용자에게 별도로 안내한다.
- `POST /api/pin-login` → `cp_pin_login`: 성공 시 임의의 256bit 세션 토큰을 발급한다.
- 기존 `GET/PUT /api/board`는 세션 토큰을 검사하는 PIN 전용 RPC를 사용한다.
- `POST /api/pin-logout`은 DB 세션을 즉시 삭제한다. 세션 유효 12시간,
  브라우저 메모리에만 보관하므로 새로고침하면 4자리 비밀번호를 다시 입력한다.
- 잘못된 비밀번호 5회 연속 입력 시 전체 보드에서 15분간 잠근다. 제한은 DB에
  저장되어 Worker 재시작이나 RPC 직접 호출로 초기화되지 않는다.
- 세션은 DB에 SHA-256 해시만 저장한다. PIN/세션 테이블 직접 조회 권한은 없다.
  공개 RPC는 SECURITY INVOKER이며 권한 상승 구현은 비공개 스키마에 둔다.
  권한 상승 함수는 비밀번호 또는 유효 세션 검사 후에만 고정 소유자 초안에 접근한다.
- 기존 사용자 UUID·초안·버전·저장 요청 재시도 규칙은 유지한다.

## 종목명 검색

한국투자증권 공개 마스터에서 3,488개 종목의 이름·코드·시장·종류를 확보했다.
KOSPI/KOSDAQ의 숫자 6자리 주식·ETF만 현행 보드 입력 계약에 포함한다.
KONEX, 영문 혼합 코드, ETN 등은 이 검색 범위에 포함하지 않는다.

종목 등록에서 이름을 2자 이상 입력하면 검색한다. 이름이 하나와 정확히 일치하면
코드를 자동 입력하고, 유사명은 최대 20개 목록에서 선택한다. 삼성전자와
삼성전자우는 다른 종목으로 표시한다. 코드 검색과 기존 직접 입력도 유지한다.
이름 변경 시 이전에 자동으로 채운 코드를 지워 잘못된 연결을 방지한다.
한글 조합 중간 검색·늦게 도착한 결과·네트워크 실패를 처리한다.

`web/data/symbols.json`은 수집 시각·원본 URL·체크섬이 포함된 공개 검색 자료다.
가격·매매 가능 상태를 의미하지 않으며 종목 추천·자동 편입 기능이 아니다.
새 상장·이름 변경은 다음 갱신·배포 후 반영된다. 자동 정기 갱신은 아직 없다.

```sh
python tools/update_symbol_directory.py
```

필드 기준: 한국투자증권 공식 종목 마스터의 코드 9byte·ISIN 12byte·CP949 명칭
40byte·종류 2byte를 독립 파서로 읽는다. 다운로드·검증 실패 시 기존 파일을 보존한다.
참고: https://github.com/koreainvestment/open-trading-api/tree/main/stocks_info

## 실제 DB 적용·검증

- `board_pin_access`, `board_pin_private_gateways` 두 마이그레이션 적용 완료.
- `supabase/tests/pin_access.sql`: 4자리 형식·잘못된 PIN·로그인·읽기·저장·로그아웃·
  잠금·잠금 만료·테이블 권한의 13개 assertion 통과. 테스트 변경은 rollback했다.
- 실제 Data API에서도 새 PIN 로그인·초안 읽기·로그아웃이 성공했다.
- 공개 스키마의 privileged 함수 경고는 비공개 구현/공개 invoker 경계로 해소했다.
- 마지막 security advisor에는 기존 Supabase Auth의 leaked-password protection
  비활성 경고만 남았다. 새 PIN 로그인은 Supabase 이메일 Auth를 사용하지 않는다.
  기존 계정 설정은 변경하지 않았다.
  안내: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection
- Node: 62개 통과. Python REST: 166개 통과. 새 파서·테스트 Ruff/format 통과.
- Wrangler dry-run 빌드, JS 구문 검사·diff 검사 통과.

## 운영 반영·인수

이전 Worker 배포 버전 `68791d5c-b2e1-452b-addd-54ea3b5d8678`는 사용자 로그에서
성공을 확인했고, 운영 HTML/API도 확인했다. 사용자 브라우저에서 이전 화면이
가입 실패를 일반 메시지로 표시하는 상태와 콘솔 오류 없음도 확인했다.
현재 변경은 새 Worker 배포가 필요하다. 모든 JS/CSS URL의 버전을 갱신하고
HTML/JS/CSS는 재검증하도록 응답 캐시를 보완했다. 초기화 실패도 별도로 안내한다.

```powershell
git pull --ff-only origin main
npx wrangler deploy
```

배포 후 Ctrl+F5 → 4자리 비밀번호 → 보드 열기 → 이름으로 종목 검색 →
목록 선택/코드 자동 입력 → 종목 추가 → 서버 저장·불러오기를 확인한다.
실제 PIN 화면 브라우저 인수·모바일 실기기 확인은 재배포 후에 진행한다.
시세·계좌·엔진·주문 연결과 R04/R05 지정 PC 실증은 이번 범위 밖이다.

## 운영 검색 오류 수정 — 브라우저 타이머

배포 후 사용자 Chrome에서 자동 검색과 검색 버튼이 모두 `TypeError: Illegal
invocation`으로 중단되는 것을 직접 확인했다. 운영 HTML·검색 JS·3,488개 종목
JSON은 모두 HTTP 200이었다. 오류는 타이머 함수를 객체 메서드로 보관하면서
호출 수신자가 Window에서 일반 객체로 바뀐 데 있었다. 기존 테스트는 주입한
가짜 타이머만 사용해 브라우저 기본 어댑터 오류를 놓쳤다.

기본 어댑터는 `globalThis.setTimeout/clearTimeout`을 명시적으로 호출하는
래퍼로 수정했다. Window 수신자를 요구하는 브라우저 환경 모사 회귀 검사로
한글 조합·입력 자동 검색·검색 버튼·폼 초기화를 확인했다. Node 총 63개와
Worker 빌드·diff 검사를 통과했다. 배포 전 실제 브라우저 성공으로 표시하지 않는다.

기존 보드 카드 필터는 **등록한 종목에서 찾기**로 명칭을 바꿨다. 새 종목은
**＋ 종목 등록 → 종목명 → 종목명으로 코드 찾기**에서 찾는다.
JS/CSS 캐시 버전은 `20261026-search-timer-fix`로 올렸다.
최신 main 재배포 후 삼성전자 검색 → 005930 자동 입력 → 삼성전자우 선택 시
005935 전환과 콘솔 오류 없음을 실제 Chrome에서 확인해야 한다.
