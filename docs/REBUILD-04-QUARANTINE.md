# REBUILD-04 가상 체결 격리와 재처리

2026-09-15. [대조 해소](REBUILD-04-RECONCILIATION.md)에 이은 내부 가상 실행 기반 구현이다.

## 구현한 흐름

`QUARANTINED_FILL`은 가상 원본 이벤트 ID, 주문번호, 종목, 체결량, 잔량, 증거 버전을 보존한다. 수량에는 반영하지 않고 해당 종목을 대조 상태로 둔다. 주문·배정이 없는 종목도 재시작 검토에서 차단한다.

`execution.quarantine.reprocess`는 격리 ID, 근거 참조 코드, 검토한 원장 revision을 받는다. 같은 범위의 ACK 주문번호가 정확히 하나의 논리 주문에 연결되고 원주문 종목이 일치할 때만 체결을 연결한다. 연결이 없거나 여러 주문에 걸치면 거절한다. 종목·가격·시간만으로 추측하지 않는다.

연결된 FILL과 QUARANTINE_RELEASED를 같은 SQLite 트랜잭션으로 기록한다. 두 기록 모두 outbox에 반영되며 격리 해제 기록의 발행이 실패하면 앞선 체결 기록도 롤백된다. 원래 격리 사실은 삭제하지 않는다. 격리 이벤트 ID에서 파생한 고정 체결·해제 ID를 사용하므로 재처리 재시도와 원본 재수신은 수량을 다시 늘리지 않는다. 같은 해제 요청의 근거 코드를 바꾸면 충돌이다.

재처리는 수신 증거를 원장에 반영하는 경로이므로 시작 게이트가 닫혀 있어도 계좌 잠금 소유하에 수행할 수 있다. 주문을 전송하거나 게이트를 자동으로 열지는 않는다. 다른 격리·불일치·주문 수량 충돌은 그대로 남는다.

## 적용 제한

현재는 타입이 검증된 **가상 체결의 필드 값**을 보존한다. 원본 JSON의 공백·키 순서 같은 바이트 표현, 파싱 불가능한 메시지, 실제 키움 원문을 보관하는 범용 수신함은 구현하지 않았다. 계좌·토큰 등 민감정보가 포함될 수 있는 실제 원문을 이 경로에 넣지 않는다. 실제 어댑터에는 별도 보관 위치·마스킹·보존 기간·오류 원문 정책이 필요하다.

가상 이벤트 ID와 주문번호 연결의 신뢰성은 테스트 시나리오가 제공한다. 실제 키움 체결 ID의 유일성, 주문번호 재사용 범위, 직접 체결 수신과 격리 재처리 사이의 동일 체결 식별은 미확인이다. 이 구현을 실제 주문 어댑터 활성화 근거로 사용하지 않는다. 현재 격리 대상은 체결이며 다른 콜백 형식과 수동 외부 거래의 배정은 후속 작업이다.

## 검증

- 신규 6개 포함 전체 pytest **92개 통과, 7.06초**.
- 격리 중 수량 불변·시작 차단, 정확한 연결 후 한 번 반영, 미연결·중복 주문번호·오래된 검토 거절, 격리 해제 발행 실패 시 체결까지 롤백을 확인했다.
- Ruff ALL·basedpyright 오류/경고 0. 코드 규칙과 포맷 32개 파일 통과.
- 직접 가상 실행에서 격리 중 관리량 0, 접수 근거 도착 후 재처리 True, DB 재로드 후 관리량 30, 원본 보존 True, 중복 재처리 False를 관측했다.

실제 증권사 호출·주문·배포·운영 DB 변경은 수행하지 않았다. 다음은 실제 조회 근거의 완전성 모델과 외부 명령 인증·권한, 패턴 상세 설정이다.
